1. UDP 패킷 구조 (ESP32-S3 → sensing)

UDP:5005 수신 · sensing/main.py parse_packet() · 전처리 후 csi:raw 적재

1.1 현재 패킷 포맷 8B 헤더 + 가변 페이로드

현행 sensing/main.py의 parse_packet() 기준. 헤더 8바이트(리틀엔디안) + n_samples×float32 페이로드.

Offset필드struct타입Bytes설명
0node_idBuint81노드 번호 1~6 (0 = 레거시/미식별)
1seqBuint81패킷 순서. 256에서 랩어라운드 (loss 계산 시 %256)
2n_samplesHuint162페이로드 float32 샘플 개수
4ts_msIuint324신호 발생 시각 (Unix ms 하위 32비트)
8payload{n}ffloat32[]4·n전처리 전 raw CSI 샘플 (subcarrier amplitude)
현재는 매직헤더 없음 → 깨진 패킷은 except로 “레거시 패킷” 처리되어 통째로 float32 해석되는 취약점이 있음. rssi 없음 → 신호 품질 모니터링 불가. seq가 uint8 → 빠른 전송 시 256 주기로 loss 카운트 왜곡 가능.
1.2 레퍼런스에서 추출한 “있으면 좋을” 필드 CSI 레포

레퍼런스 패킷 "<4s8sIIi64f" (280B 고정)에서 우리 스케일에 유효한 3가지를 발췌.

추출 필드레퍼런스 타입도입 효과우리 적용
header_tag 추출char[4] = "CSI!"패킷 무결성 검증 — 깨진/타 프로토콜 패킷 즉시 폐기. 레거시 fallback 취약점 제거4B 매직 추가
seq_num 확장uint32 (I)uint8→uint32로 랩어라운드 사실상 제거 → loss_rate 정확도 향상node:{N}:health.last_seq 호환
rssi 신규int32 (i, signed)신호 세기(dBm) 확보 → 노드 신호 품질·위치 이탈 감지. 음수 표현 위해 signednode:{N}:health에 rssi 필드 추가
참고 (CSI 의미): PRE 레포 기준 CSI는 64 subcarrier amplitude (0~150). 우리 M1 입력은 전처리 후 (1×1×192×100) 텐서이므로, raw subcarrier amplitude를 가변 길이로 받아 sensing에서 전처리하는 현행 구조를 유지하되 패킷 헤더만 보강하면 됨.
1.3 권장 통합 헤더 20B 헤더 + 가변 페이로드

현행 가변 페이로드 방식 유지 + 추출 3필드 반영. struct 포맷 "<4sBBHIIhH" = 20바이트 헤더.

4node_idBuint81노드 번호 0~6

헤더 20B는 4바이트 정렬됨. 하위호환: magic 검사 실패 시 1.1 현행 8B 파서로 폴백하면 무중단 마이그레이션 가능.
