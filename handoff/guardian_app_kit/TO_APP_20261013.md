서버 브랜치: `codex/app-integration-test`

## 1. 서버에서 바뀐 것

- Redis 의존 API가 Redis 장애 시 503 `redis_unavailable`을 반환한다.
- `/notify/*`는 FCM 오류를 409·410·422·502·503으로 구분하며 토큰·키 경로·내부 예외 문구를 응답에 넣지 않는다.
- 잘못된 `/history?before`와 경보 `msg_id`는 Redis 조회 전에 400으로 거절한다.
- 빈 FCM 토큰과 잘못된 `device_id` 형식은 422로 거절한다.
- `monitor.html`은 Firebase 준비·등록 기기 수로 앱 연동 ON/OFF를 표시하고, 토큰을 노출하지 않는 일반/응급 테스트 알림 버튼을 제공한다.
- 응급 시험은 `type=emergency`, `test=1`, `speech_text=살려줘`를 보내고 제목·본문에 `[시험]`을 넣는다. 실제 사고 이력·Phase 2는 생성하지 않는다.
- 오류별 앱 처리 기준은 `docs/02_API_SPEC.md` 6절에 정리했다.

## 2. 10-13 노트북 사전 확인

| 항목 | 결과 | 주장 범위 |
|---|---|---|
| 앱 토큰 등록 | 1대 등록 확인 | 노트북 로컬 Redis |
| `POST /notify/test` | 200, Firebase 메시지 ID 반환 | Firebase 발송 접수 |
| 휴대폰 실제 표시 | 미확인 | 앱 화면·알림음 확인 필요 |

시험 당시 노트북 주소는 `http://192.168.0.11:8000`이었으나 DHCP 주소이므로 고정값으로 넣지 않는다. 앱은 시험 직전에 전달받은 서버 주소를 사용한다.

## 3. 앱에서 확인해 줄 것

1. 앱 시작·`onNewToken`·30분 주기로 `POST /auth/register-token`을 다시 호출한다.
2. 400·409·410·422·502·503을 `docs/02_API_SPEC.md` 6절에 맞춰 처리하고 같은 잘못된 요청을 무한 반복하지 않는다.
3. 시스템 알림 형식과 data-only 형식을 모두 처리하는지 알려준다. data-only 지원 확인 전 서버의 `FCM_DATA_ONLY=true` 전환은 보류한다.
4. 시험 알림이 포그라운드·백그라운드·앱 종료·화면 잠금·무음·방해금지·절전 상태에서 어떻게 보이는지 각각 기록한다.
5. 실제 응급 푸시의 `msg_id`로 `seen` 또는 `called` ack를 보내고, 서버 `acked_by`에 같은 `device_id`가 기록되는지 함께 확인한다.

## 4. 함께 진행할 RPi5 시험

- RPi5의 실제 IP·커밋·컨테이너 이미지·`FCM_DATA_ONLY`·`APP_EXPECTED_NODES`·`VOICE_ENABLED`를 먼저 기록한다.
- 앱 토큰을 RPi5에 다시 등록하고 일반 시험 푸시 1회를 보낸다.
- 승인된 16 kHz mono PCM 음성 1건으로 M4→규칙 경보→FCM→앱 표시→ack를 한 번만 수행한다.
- 200 응답이나 `notify:sent`만으로 휴대폰 수신 성공이라고 기록하지 않는다.
- 토큰, Firebase 서비스 계정 키, 전사 원문은 공유 자료에 넣지 않는다.
