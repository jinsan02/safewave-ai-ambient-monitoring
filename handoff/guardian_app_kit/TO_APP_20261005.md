# 보호자 앱 연동 전달 (2026-10-05, 노진산 → 이대경)

서버(통합) 쪽 앱용 API는 준비를 마쳤다. 이 문서는 **앱을 실제 서버에 붙이는 데 필요한 값과 순서, 앱 쪽에 요청하는 것**만 담는다.
- 상세 계약: `docs/02_API_SPEC.md`
- 응답·푸시 예시: `mock/`
- 실기기 알림 확인 항목: `docs/03_ANDROID_ALERT_RELIABILITY.md`

## 1. 서버 상태 (10-05 노트북에서 실제 호출로 확인)
| 기능 | 상태 |
|---|---|
| 토큰 등록·삭제, 테스트 푸시, 홈 요약, 이력(페이지), 노드 상태, 서버 상태, 설정 조회, 오탐·미탐 신고 | 동작 |
| **경보 확인(새)**: `POST /alerts/{msg_id}/ack`, `GET /alerts/{msg_id}`, 이력의 `acked_by`, 다른 보호자에게 `ack` 푸시 | 동작(10-05) |
| 음성 확인 결과 `voice_ok`(대상자가 괜찮다고 했는지) | 동작. 빈 방 시험에서 무응답 → `false` 확인 |
| **실제 푸시 발송** | **아직 안 됨** — 서버에 Firebase 키가 없다(2절) |
| 인증(API 키) | 없음 → 같은 와이파이 시연 전용(결정 대기) |

## 2. 키·설정 — 누가 무엇을 준비하나
**키 파일은 Git·카톡·문서에 붙이지 않는다.** USB나 개인 드라이브 링크처럼 대화 기록에 남지 않는 방법으로 직접 전달한다.

| 항목 | 누가 | 어디에 | 비고 |
|---|---|---|---|
| Firebase 프로젝트 | 앱 담당(이대경)이 만들고 노진산을 구성원으로 추가 | Firebase 콘솔 | 앱과 서버가 **같은 프로젝트**를 써야 푸시가 간다 |
| `google-services.json` | 앱 담당 | 앱 저장소 `app/` | 앱 패키지명으로 등록(예: `com.safewave.guardian`, 결정 D10). Git에 올릴지 팀 규칙으로 정한다 |
| 서비스 계정 키(JSON) | 앱 담당이 콘솔에서 만들어 노진산에게 전달 | 서버 `api/auth/firebase_key.json`(노트북·RPi5 각각) | Git 제외 경로. 넣은 뒤 API를 재시작하면 `/app/summary`의 `fcm_ready`가 `true`가 된다 |
| 서버 주소 | 노진산 | 앱 설정 화면 입력값 | 노트북 `http://192.168.1.11:8000`, RPi5 `http://192.168.1.2:8000`(공유기 자동 배정이라 바뀔 수 있음). 폰이 같은 와이파이여야 한다 |
| 푸시 형식 | 노진산 | 서버 환경변수 `FCM_DATA_ONLY` | **앱을 설치하는 날 `true`로 바꾼다.** 그 전(`false`)에는 시스템이 알림을 띄워 전체 화면 경보·사이렌이 안 된다 |
| 기기 ID | 앱 | 앱 저장소(설치 시 1회 생성) | 설치마다 UUID를 만들어 보관한다. 기본값 `galaxy_flip4`를 쓰면 보호자끼리 덮어쓴다 |

## 3. 연동 순서
1. 앱: Firebase 연결 → FCM 토큰 받기 → `POST /auth/register-token` `{"token","device_id"}`
   - 다시 등록하는 때: 앱 시작, `onNewToken`, 30분마다. 서버는 1시간 보관한다.
2. 서버(노진산): 키를 넣고 API 재시작 → `fcm_ready=true` 확인
3. 앱: 설정의 "테스트 알림" → `POST /notify/test` `{"token"}` → 폰에 도착하는지 본다
4. 서버: `FCM_DATA_ONLY=true` 전환 → 앱 종료·잠금·무음 상태에서 응급 푸시 확인(`03` 문서 항목)
5. 화면별 연결
   - 홈 `GET /app/summary`
   - 이력 `GET /history?n=50&before=<마지막 _id>`
   - 경보 상세 `GET /alerts/{msg_id}`
   - 확인 버튼 `POST /alerts/{msg_id}/ack` `seen|called`
   - 오탐 신고 `POST /alerts/{msg_id}/feedback`
   - 센서 `GET /nodes/health`
   - 로그아웃 `DELETE /auth/register-token/{device_id}`

빠른 확인(같은 와이파이의 PC에서)
```bash
curl http://192.168.1.11:8000/app/summary
```
```bash
curl "http://192.168.1.11:8000/history?n=1&level=critical"
```
```bash
curl -X POST -H "Content-Type: application/json" -d "{\"device_id\":\"test-pc\",\"action\":\"seen\"}" http://192.168.1.11:8000/alerts/<msg_id>/ack
```

## 4. 앱 쪽에 요청하는 것
1. **Firebase 프로젝트 생성과 서비스 계정 키 전달**(2절 방법으로). 이게 없으면 실제 푸시를 시험할 수 없다.
2. **패키지명·앱 이름 확정**(D10). Firebase 앱 등록에 필요하다.
3. **푸시 유형 5가지를 모두 처리**: `emergency`, `voice_ok`, `ack`(새), `heartbeat`, `test`. `type`이 없고 `risk_level=critical`이면 `emergency`로 처리한다(구버전 호환). data 값은 모두 문자열이다.
4. **경보 확인 흐름**
   - 응급 알림 화면에 "확인함(seen)"과 "전화함(called)" 버튼을 둔다.
   - 다른 보호자의 `ack` 푸시를 받으면 경보 화면에 "○○가 확인함"을 표시한다.
   - 1시간이 지나면 서버 기록이 사라지므로, 확인 기록은 앱에도 저장한다.
5. **`voice_ok` 표시**
   - `true`: "대상자가 괜찮다고 응답"(그래도 전화 확인 권장)
   - `false`: "무응답·도움 요청"
   - `null`: 표시 안 함
6. **오류 처리**(02 문서 6절): 서버 연결 실패 시에도 "응급 알림은 계속 받습니다"를 표시하고, 없는 API(404)는 "준비 중"으로 둔다.
7. **실기기 결과 공유**: 플립4에서 잠금·무음·방해금지·절전·앱 종료 상태별 수신 여부와 앱 버전을 공유한다(03 문서 표 양식).
8. 표시하지 않는 것: 음성 전사 원문(`transcript_ko`), 생체신호(`experts.vital`).

## 6. 참고
- 지금 노트북 스택은 낙상 모델(M1)의 빈 방 오경보 때문에 약 90초마다 `낙상 확정(M1 3/5)` 경보가 쌓인다. 앱 시험에는 오히려 데이터가 되지만, **실제 사용 전에는 M1 단독 경보를 끈다**(팀 결정 대기).
- 서버 저장은 모두 1시간 TTL이다. 앱이 오래 보관할 기록(확인·신고 이력)은 앱 로컬에 둔다.
