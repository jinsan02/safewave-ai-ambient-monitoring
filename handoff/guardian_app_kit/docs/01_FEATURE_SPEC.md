# 기능 명세 — SafeWave 보호자 앱 (Android)

## 1. 목적과 사용자
- 사용자: 독거 어르신의 보호자(주로 5060 자녀). 여러 명일 수 있다.
- 목적: 응급을 **놓치지 않고 즉시** 알리고, 확인·연락·오탐 신고까지 한 화면에서 끝내게 한다.
- 대상 기기: Galaxy Z Flip 4 (Android). iOS 범위 밖.

## 2. 분류 기준
| 등급 | 의미 |
|---|---|
| **MVP** | 프로토타입(10월)에 반드시 동작 |
| **P1** | MVP 직후, 서버 작업이 작음 |
| **P2** | 향후 — 비용·제휴·동의·서버 대규모 작업 필요 |
| **제외** | 정책 위반, 현재 시스템으로 불가, 또는 근거 없음 (`06_LEGACY_SPEC_AUDIT.md`) |

## 3. MVP 기능

| ID | 기능 | 내용 | 서버 의존 |
|---|---|---|---|
| **F1** | 첫 실행·연결 | 서버 주소 입력 → `GET /` 확인 → 권한 안내 4종(알림, 전체 화면, 배터리 최적화 예외, 방해금지 예외) → 토큰 등록 → 테스트 알림 수신 확인 | 있음 |
| **F2** | 응급 전체 화면 경보 | data 푸시 수신 → `emergency_alarm` 채널 알림 + full-screen intent → 잠금 화면 위 경보 화면. 고대비·큰 글씨, 사유·시각·판단 경로 표시 | **S0** |
| **F3** | 알람 소리 반복 | `USAGE_ALARM`으로 사이렌·진동, **확인 버튼을 누를 때까지 반복**(최대 시간은 설정, 기본 5분). 알람 음량을 올렸다면 종료 시 원래대로 복구 | S0 |
| **F4** | 경보 화면 행동 | 버튼 4개: **대상자에게 전화**, **119 전화**(둘 다 전화 앱으로 연결, 자동 발신 아님), **확인했음**, **오탐 신고** | 오탐 신고는 서버 완료(`POST /alerts/{msg_id}/feedback`), 확인은 S2 전까지 로컬 기록 + "서버 미연동" |
| **F5** | 응답 확인 반영 | `voice_ok` 푸시 수신 시 해당 경보에 "대상자가 괜찮다고 응답" 표시(일반 알림) | 있음 |
| **F6** | 알림 이력 | 받은 푸시를 로컬(Room)에 최근 100건 보관 + 서버 `GET /history` 병합(닿을 때만), 중복 제거 | 있음 |
| **F7** | 홈 | 현재 상태(정상/경고/응급, 색+글자), 마지막 갱신 시각·지연, 센서 온라인 n/3, 서버 상태, 최근 경보. 서버에 못 닿으면 "집 네트워크 밖 또는 서버 정지 — 응급 알림은 계속 받습니다" | 있음 |
| **F8** | 설정 | 서버 주소, API 키(선택), 기기 ID(보기), 보호 대상 이름·전화번호(기기에만 저장), 경보 반복 시간, 알림 테스트, 등록 상태 | 있음 |
| **F9** | 연결 유지 | 앱 시작·`onNewToken`·WorkManager(30분)로 토큰 재등록. 권한·채널이 꺼져 있으면 홈 상단에 경고와 설정 이동 버튼 | 있음 |
| **F10** | 여러 보호자 | 설치마다 고유 기기 ID(UUID) → 서버는 등록된 모든 기기에 동시에 보낸다 | 있음 |

### MVP 완료 기준 (플립4 실기기)
- [ ] 앱 종료 + 화면 잠금 + 무음에서 응급 푸시 → 전체 화면 경보와 사이렌
- [ ] 방해금지 모드(앱 예외 허용 상태)에서 위와 동일
- [ ] 접힌 상태에서 커버 화면 알림 + 소리 → 펼치면 경보 화면
- [ ] 전체 화면 권한을 거부해도 고우선순위 알림 + 반복 소리로 동작(단계적 저하)
- [ ] 확인 버튼 → 소리 정지, 이력에 "확인함" 기록
- [ ] `voice_ok` 푸시가 해당 경보에 반영
- [ ] 서버 1시간 이상 정지 후 재시작 → 토큰 재등록으로 푸시 복구
- [ ] 서버 불통·"no data yet"·503·404(미구현 API)를 각각 올바르게 표시
- [ ] 보호자 기기 2대가 같은 경보를 동시에 받음

## 4. P1 (MVP 직후)

| ID | 기능 | 서버 |
|---|---|---|
| P1-1 | 미확인 재발송: N분 동안 아무 기기도 확인하지 않으면 서버가 다시 보냄 | S2 + S10 |
| P1-2 | 시스템 정지 감지: 서버가 매일 "정상 동작" 푸시, 앱은 26시간 미수신 시 로컬 경고 | S9 |
| P1-3 | 안부 다시 묻기: 대상자 집 스피커에서 TTS로 다시 질문(음성 서비스를 띄운 경우) | 새 엔드포인트(기존 TTS 큐 재사용) |
| P1-4 | 방 이름: 노드 번호 대신 "거실" 등(소리 기반 경보에만 의미 — 낙상은 위치를 모름) | S8 |
| P1-5 | API 인증 | S6 |
| P1-6 | 추세 차트(최근 1시간 위험도) | 있음(`/charts/minute`) |
| P1-7 | 실시간 상태(웹소켓, 앱 전면일 때만) | 있음(`/ws/monitor`) |

## 5. P2 (향후)

| 기능 | 필요 조건 |
|---|---|
| 사고 전후 음성 클립 재생 | 연속 오디오 버퍼(현재는 소리 날 때만 최대 6초 조각), 원격 접속, 대상자 동의·보관 정책 |
| 자동 음성 전화·SMS 에스컬레이션 | 외부 서비스(유료), 국내 발신 가능 여부, 서버 연동(Python) |
| 지자체 관제센터 연계 | 기관 협약 |
| 보호자가 원격으로 직접 말 걸기 | 양방향 음성 스트리밍 |
| iOS 앱 | 별도 개발, Critical Alerts는 Apple 승인 필요 |

## 6. 제외 (이유는 `06_LEGACY_SPEC_AUDIT.md`)
접근성 서비스 오버레이, 벨소리 모드 강제 변경(`setRingerMode`), WakeLock 직접 제어, 상시 포그라운드 서비스,
`ROLE_EMERGENCY`, CSI 파형 첨부, 장소 단정("욕실 낙상"), "1분간 움직임 없음" 요약, 도달률·오탐률 수치 약속.

## 7. 화면 목록

| 화면 | 진입 | 핵심 요소 |
|---|---|---|
| 온보딩 | 첫 실행 | 서버 주소, 권한 4단계, 테스트 알림 |
| 경보(전체 화면) | 응급 푸시 | 빨간 배경·흰 글자, "응급 상황", 사유, "N분 전 (HH:MM)", 판단 경로, 버튼 4개 |
| 홈 | 앱 실행 | 상태 카드, 갱신 시각, 센서·서버 상태, 최근 경보, 권한 경고 배너 |
| 알림 이력 | 탭 | 목록(등급 색+글자), 확인 여부, 당겨서 새로고침 |
| 알림 상세 | 이력·알림 탭 | 경보 정보, 응답 확인 여부, 확인·신고 상태, 전화 버튼 |
| 센서 상태 | 탭 | 노드별 온라인·손실률·RSSI(설치된 노드만) |
| 설정 | 탭 | F8 항목 |

UI 원칙: 본문 18sp 이상, 경보 화면 제목 32sp 이상, 명도 대비 7:1 이상 목표, 상태는 색과 글자를 함께, 버튼 최소 56dp.

## 8. 표시 금지·주의
- `experts.vital`(심박·호흡): 미학습 모델 — 표시하지 않는다.
- `experts.speech_ko.transcript_ko`(음성 전사): 개인정보 — 표시하지 않는다(키워드만 가능, 결정 전).
- 점수는 참고용 작은 글씨. "확률 85%"처럼 해석하지 않는다.
- 낙상 경보에 방 이름을 붙이지 않는다(모델이 위치를 판단하지 않음).
