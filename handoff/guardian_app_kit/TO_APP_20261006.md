- 앱 기기 토큰 1대(`9f24ce6c-…`)는 서버 쪽에서 RPi5로 옮겨 두었다. 앱이 다시 등록할 때도 RPi5 주소로 보내야 한다.
- RPi5에서 긴급 음성 경보가 빨라졌다: "도와주세요" → 폰 발송 **약 5.5초**(전에는 16.9초). 노트북 GPU는 0.7초.
- 10-05 문서 6절의 "약 90초마다 낙상 확정(M1 3/5) 경보가 쌓인다"는 더 이상 맞지 않다. 낙상 모델이 보드 추론 방식으로 바뀌었고, 지금은 **낙상 감지(M1)가 꺼져 있다**(규칙을 다음 주 실측으로 정한 뒤 켠다).

## 1. 먼저 확인해 줄 것 — 확인 버튼이 서버에 안 들어온다
10-05 검증 중에만 시험 푸시가 적어도 4번(노트북 1 · RPi5 3) 기기에 발송됐는데, **확인(ack)은 한 번도 서버에 들어오지 않았다.** 확인할 것:
1. 응급 알림 화면에 "확인함(`seen`)" · "전화함(`called`)" 버튼이 있는가
2. 요청 주소가 RPi5인가: `POST http://192.168.1.2:8000/alerts/{msg_id}/ack`
3. 요청 형식이 맞는가
   - 본문 JSON: `{"device_id": "<등록한 device_id>", "action": "seen"}`
   - `device_id`는 영문·숫자로 시작, 64자 이하(`^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`)
   - `action`은 `seen` 또는 `called`만 받는다
   - 형식이 틀리면 서버가 422를 돌려준다
   - `msg_id`는 응급 푸시 data의 `msg_id` 값을 그대로 쓴다(예: `1791208958385-0`)
4. 성공하면 `GET /alerts/{msg_id}`의 `acked_by`에 기기가 보이고, 다른 등록 기기에는 `type=ack` 푸시가 간다.

같은 와이파이의 PC에서 시험:
```bash
curl -X POST -H "Content-Type: application/json" -d "{\"device_id\":\"test-pc\",\"action\":\"seen\"}" http://192.168.1.2:8000/alerts/<msg_id>/ack
curl http://192.168.1.2:8000/alerts/<msg_id>
```

## 2. 앱에서 바로 할 수 있는 것 (서버 변경 없음)

### 2-1. 토큰 등록: 앱을 열 때마다 + 토큰이 바뀔 때마다
- 서버는 토큰을 Redis에 1시간 단위로 저장하고 계속 연장한다. **RPi5나 Redis가 재시작되면 토큰이 사라진다.**
- 그래서 앱 시작 시와 `onNewToken` 때마다 `POST /auth/register-token` `{"token": "...", "device_id": "..."}`를 보낸다. 실패하면 다음 실행 때 다시 보낸다.
- 등록 확인: `GET /auth/tokens`의 `devices`에 자기 `device_id`가 있으면 된다.

### 2-2. 경보 사유를 알림 첫 줄에 표시
응급 푸시 data에는 이미 다음 값이 실려 간다(모두 문자열):

| 키 | 예 | 표시 |
|---|---|---|
| `summary` | `긴급 음성 '도와주세요'(≈도와주세요, 유사도 1.00)` · `낙상 확정(M1 3/5)` | **알림 본문 첫 줄** |
| `slm_mode` | `rule` | `rule`이면 "즉시 경보"(규칙). 그 밖의 값은 AI 종합 판단 |
| `node_id` | `1` | 위치 이름으로 바꿔 표시(노드 ↔ 방 이름 표는 앱 설정) |
| `ts_ms` | `1791208953032` | 발생 시각 |
| `risk_level` / `risk_score` | `critical` / `0.65` | 점수는 작게만. 보호자에게 숫자는 의미가 적다 |

- `summary`의 괄호 안(유사도 등)은 잘라도 된다.
- 음성 전사 원문과 생체신호는 계속 표시하지 않는다.

### 2-3. 같은 사건은 한 화면으로 묶기
- 한 사건에 응급(`emergency`) → 다른 보호자 확인(`ack`) → 음성 확인 결과(`voice_ok`) 푸시가 따로 온다. 셋 다 같은 `msg_id`를 가진다(`voice_ok`는 `msg_id`가 있을 때).
- `msg_id` 기준으로 경보 카드 하나에 시간순으로 쌓는다.
  - 예: "22:58 긴급 음성 감지 → 22:58 ○○ 확인함 → 22:59 대상자 응답 없음"
- 이미 확인한 경보에 다시 알림음을 울리지 않는다.

### 2-4. 감시 상태 표시 — "낙상 감지 꺼짐"
- `GET /app/summary`에 이미 다음 값이 있다.
  - `monitoring.m1`(낙상 감지 켜짐 여부), `monitoring.ai_enabled`
  - `nodes_online` / `nodes_expected`
  - `data_age_s`(마지막 분석 결과가 몇 초 전인지)
- 홈 화면 상단에 띠를 표시한다.
  - `monitoring.m1 == false` → "낙상 감지 꺼짐 (음성·소리 감지는 동작)"
  - `ai_enabled == false` → "분석 꺼짐"
  - `nodes_online < nodes_expected` → "센서 n대 연결 안 됨"
  - `data_age_s > 60` 또는 서버 연결 실패 → "서버 응답 없음 — 응급 알림은 계속 받습니다"
- **지금은 낙상 감지가 꺼져 있으므로 이 띠가 떠야 정상이다.**
