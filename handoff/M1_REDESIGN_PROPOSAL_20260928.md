# M1 재설계 제안 — 정확도를 올리려면 무엇이 더 필요한가 (2026-09-28, 로컬)

작성: 노진산(통합). 전제: 재학습·구조 변경 모두 허용. 근거와 수치는 `handoff/M1_SUMMARY_20260928.md`에 있다.
**표시 규칙**: [측정]은 우리 데이터로 잰 값, [추정]은 가정에 기댄 계산, [문헌]은 논문·제조사 자료다.

## 1. 잡음을 낮추고 모아서 추론하면 정확도가 오르나?
| 조치 | 무엇이 좋아지나 | 한계 |
|---|---|---|
| 잡음 낮추기(종류별 배경 빼기) | 빈 방 잡음 바닥 3~4배 감소 [측정] → **큰 움직임은 더 확실히 잡힌다** | '낙상'과 '빨리 앉기·눕기'를 가르는 정보는 늘지 않는다 |
| 모아서 판단(5초 + 히스테리시스) | 판단 바뀜 65배 감소 [측정] | 모델이 치우쳐 있으면 치우친 채로 굳는다 [측정: '낙상 상태' 26~30% 유지] |
| 데이터 더 모으기 | 다양한 조건이면 새 날·새 배치에 버틴다 [문헌] | 같은 조건을 반복하면 그 세션만 외운다 [측정: 같은 날 1.3%, 다른 날 96%] |

→ **셋 다 필요하지만 셋으로 충분하지 않다.**
- 우리 CSI는 안테나 1개, 세기만(위상 없음), 20 MHz, 프레임마다 최댓값 정규화다. 이 조건에서 **'큰 움직임 사건'은 잘 잡을 수 있지만 '낙상 대 낙상 비슷한 동작' 구분에는 상한이 있다.**
- 정확도를 실제로 올리는 것은 네 가지다.
  - (가) 신호 자체를 더 좋게
  - (나) 사건 단위로 판단하는 구조
  - (다) 소리·음성과의 결합
  - (라) 제대로 된 평가

## 2. 더 필요한 것 — 효과 큰 순서
### ① 신호 품질 (펌웨어·배치) — 모든 것의 전제
| 항목 | 이유 | 상태 |
|---|---|---|
| 한 종류 프레임만 받기 | 혼재가 움직임 지표를 3~4배 부풀린다 [측정] | 김태연 진행 중 |
| **수신 이득 고정** | 제조사 예제 기본값. 자동 이득 변화가 CSI 일관성을 해친다 [문헌: esp-csi] | 없음 → 제안 |
| **공유기 ping으로 일정한 트리거 + 응답 프레임만 수용** | 같은 종류·일정 간격 프레임을 확보하고, 반복 프레임(24~33%)[측정]을 줄인다 | 김태연 ICMP 트리거 있음. 수용 조건 확인 필요 |
| **프레임 최댓값(정규화 배율) 같이 보내기** | 정규화가 공통 진폭 변화를 지운다(김태연 가설). 낙상·호흡 단서일 수 있다 | CSI2에 `frame_peak` 있음 → 학습 입력에 넣어 볼 것 |
| **새 프레임 속도 ≥ 100 Hz 검토** | 몸이 움직이면 경로 길이 변화율 ÷ 파장(2.4 GHz에서 12.5 cm)으로 CSI가 출렁인다. 낙상 속도(1.5~3 m/s)면 수십 Hz까지 오를 수 있다 [문헌: CARM류 속도 모델, 추정]. **50 Hz 입력은 빠른 낙상 성분이 잘릴 수 있다** | N_pose는 50 Hz → 벤치 때 100 Hz도 재 볼 것 |
| 외부 안테나·배치 | 방 어디서든 가까운 노드 2개 이상. 먼 노드 반응 1.3배 대 가까운 노드 3.5배(김태연) | 진행 예정 |

### ② 입력 표현 — 배경이 아니라 '변화'를
| 표현 | 설명 |
|---|---|
| 종류별 배경 빼기(잔차) | 빈 방에서 가장 조용·안정 [측정]. 기본 입력 후보 |
| 속도 스펙트럼 | 잔차의 주성분(PCA) → 짧은 시간 푸리에 변환 → '얼마나 빨리 움직였나' 분포. 낙상은 짧고 빠른 폭발 뒤 정지 [문헌: WiFall·RT-Fall·FallDeFi 계열] |
| 사건 전후 배경 변화 | 사건 전 10 s 평균 모양 대 사건 뒤 10 s. '바닥에 사람이 남았나'의 단서(누우면 배경이 바뀐다) |
| 프레임 배율(`frame_peak`) | 공통 진폭 변화 복원 |

### ③ 판단 구조 — 매 창 분류에서 '사건 단위' 판단으로
```
[노드별] 잔차 급변 감지(계산 규칙) ──┐
                                   ├─ 2개 이상 노드 동시 → 사건 구간 잘라내기(전 3 s ~ 후 10 s)
[허브]   사건 분류기(작은 모델) ←────┘     특징: 급변 크기·길이, 속도 스펙트럼, 사건 뒤 정지, 배경 변화, frame_peak
          ↓ 낙상 가능성
[결합]   + M3 충격음(±3 s) + M4 긴급 음성 + 사건 뒤 무활동 → 음성 확인 → 알림
```
- 매 0.2초 창을 분류하면 하루 43만 번 판단한다. 빈 방 오판 1.3%만 돼도 수천 번이다.
- **사건 단위로 바꾸면 판단 횟수가 하루 수십~수백 번**으로 줄어든다. 그래서 같은 분류 정확도에서 오경보가 크게 준다 [추정].
- 분류기가 사건 구간만 보므로 **적은 데이터로도 학습**된다.
- 급변 감지는 학습이 필요 없다. 빈 방 검증도 끝났다(113분 최대 1.65배)[측정].

### ④ 결합 — 실제 정확도를 가장 크게 올리는 곳
- M3 낙상 충격음: 실환경 47/50 감지, 생활음 오탐 4.03회/시간(소민섭)[측정]
- **'CSI 사건 + 충격음 ±3 s'를 요구할 때 우연히 겹칠 비율** [추정, 사건이 서로 독립이라는 가정]
  - 일상 CSI 사건이 시간당 60회라고 치면: 60 × 4.03 × 6 s ÷ 3600 ≈ **시간당 0.4회**
  - 그 뒤 음성 확인으로 한 번 더 거른다.
- 재현율은 곱으로 준다: CSI 0.9 × 소리 0.94 ≈ 0.85 [추정]
  - 소리 없는 낙상(천천히 주저앉음)은 'CSI 사건 + 사건 뒤 무활동 30 s + 음성 무응답' 경로로 보완한다.
  - 소리 경로 하나만 믿지 않는 구조다.

### ⑤ 데이터와 평가
| 항목 | 제안(2주 현실안) |
|---|---|
| 수집 | 3일 이상 × 배치 2개 × 2명 × 낙상 5유형 × 4회 ≈ 낙상 120~240건. 헷갈리는 동작(앉기·눕기·물건 떨어뜨리기·주저앉기)은 그 2~3배. 날마다 빈 방 1시간 |
| 라벨 | 영상 + 화면 시계로 사건 시각 확정(마커 지연 실측) |
| 라벨 없는 대량 데이터 | 평소 생활 CSI는 싸다 → 배경 보정·자기지도 사전학습에 사용 |
| 평가 | **학습에 안 쓴 날로만.** 사건 단위 재현율(유형별), 시간당 오경보(빈 방·일상 따로), 알림까지 걸린 시간 |
| 도구 | 재현 도구(실제 경보 65건을 그대로 재현함)로 운영 전에 산출 |

## 3. 완전히 엎는다면 — 세 가지 구성
| 안 | 구성 | 장점 | 단점 | 10/12 적합 |
|---|---|---|---|---|
| **A. N_pose 유지 + 입력 교체** | 보드 내 int8 모델. 입력을 원 진폭에서 종류별 배경 빼기 잔차로. 노드별 판정 → 2개 이상 → 5초 판단 | 김태연 계획 유지. 허브 정렬 문제가 없다 | 마이크로컨트롤러 제약(50 Hz, 연산). 사건 단위 판단·결합이 어렵다 | ○ |
| **B. 허브 사건 파이프라인** | 보드는 깨끗한 CSI만 보낸다(필터·이득 고정·새 프레임 비트·frame_peak). RPi5에서 잔차 → 급변 감지 → 사건 분류기(ONNX) → 결합 | 파이썬으로 빨리 고친다. 100 Hz 가능. 사건 단위·결합이 자연스럽다 | 네트워크 지터 → 보드 시계 정렬 필요. RPi5 부하(작음) | ○(병행 후보) |
| **C. CSI는 움직임만, 낙상은 소리·음성** | CSI = 재실·활동·급변 신호. 낙상 확정 = M3 충격음 + M4 긴급 음성 + 무활동 + 음성 확인 | 가장 빠르고 안전. 이미 대부분 구현됨 | CSI의 '낙상 판별' 가치를 발표하기 어렵다 | ◎(발표 안전판) |

**제안**
- **발표(10/12) 안전판은 C로 먼저 확보한다.** A1(M1 단독 경보 중지) + 급변 감지기를 보강 신호로 넣는다.
- **본선은 A 또는 B로 간다.**
  - A와 B의 차이는 '분류기가 보드에 있느냐 허브에 있느냐'뿐이다. 입력 표현(②)·사건 단위 판단(③)·평가(⑤)는 같다.
  - 김태연 0단계 벤치 결과를 보고 정한다. 추론 시간·100 Hz 가능 여부가 기준이다.
- 어느 안이든 **5분 사람 테스트가 첫 관문**이다. 잔차 급변이 사람 움직임에 2배 이상 오르지 않으면 ②③은 다시 설계한다.

## 4. 정확도 목표(제안)
| 지표 | 목표 | 측정 |
|---|---|---|
| 빈 방 오경보 | 판정 시작 ≤ 0.1회/시간 | 학습에 안 쓴 날 1시간 이상 |
| 일상 오경보(음성 확인 전) | ≤ 1회/시간 | 일상 동작 시나리오 |
| 낙상 재현율(사건) | 유형별 ≥ 0.8 | 영상 시나리오 5유형 |
| 알림 지연 | ≤ 15 s(음성 확인 포함) | 영상 시각 대비 |

## 5. 바로 할 수 있는 일
1. 5분 사람 테스트 + 분석 스크립트(급변 신호·M1 점수·동작 구간 그래프)
2. A1 + 급변 감지기 보강 신호 로컬 구현·재현 검증(운영 반영은 합의 후)
3. 김태연 님께 제안
   - 수신 이득 고정, `frame_peak` 활용, 100 Hz 벤치
   - 입력을 잔차로 바꾸기
   - 사건 단위 평가
