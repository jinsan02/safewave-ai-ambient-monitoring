# M1(낙상) 오경보 — 통합 정리 (2026-09-28)

작성: 노진산(통합). 대상: 김태연(M1), 팀.
M1 관련 문서 4개(`M1_AUDIT`, `M1_FALSE_ALARM`, `M1_IMPROVEMENT`, `M1_INPUT_DESIGN`)와 로컬 분석(`reports/laptop/m1_deep/`)을 **한 문서로 합친 것**이다. 수치 근거는 원 문서에 있다.

---

## 1. 결론
1. **지금 M1 모델(9/16 인계)은 빈 방에서도 계속 낙상으로 판정한다.** 통합 쪽에서 모델을 고칠 수 없다.
   - 빈 방 113분: 1초 창의 **37.6%**가 낙상 판정(학습 때 빈 방 1.3%)
   - 빈 칸 없이 정렬하면 **96%**
2. **원인은 모델이 움직임이 아니라 '방의 고정된 배경 모양'을 외운 것이다.**
   - 배경(장기 평균)을 빼면 점수가 모두 0.38 한 값이 된다.
   - 시간 순서를 섞어도 점수가 그대로다.
   - 움직임이 전혀 없는 창은 오히려 0.92다.
3. **운영 중 점수가 요동친 건 방이 아니라 네트워크 흔들림 때문이다.**
   - 분별 발화율이 2~94%로 요동쳤다.
   - 노드 1 창 채움과의 상관이 0.75다.
4. **경보 65건은 오경보율이 아니다.** 90초 재발동 억제 규칙의 상한에 가까운 값이다.
5. **바로 할 일은 M1 단독 경보를 막는 것이다.** 재학습 없이 소프트웨어로 해 볼 수 있는 대안은 '급변 감지기'다. 사람 5분 테스트로 확인한다.

## 2. 재현 신뢰도
- `ai/main.py` M1 경로를 그대로 재현하니 경보가 **65건으로, 실제 기록 65건과 같다.**
- 운영 중 실측 점수 21개 중 5개는 소수점까지 같고, 13개는 0.01 이내다. 나머지 차이는 추론 시점 차이(수백 ms)에서 온다.
- 도구: `scripts/dev/m1_false_alarm_analysis.py`. 새 모델 합격 시험에 그대로 쓴다.

## 3. 원인 순위 (빈 방 오경보 기여 기준)
| 순위 | 원인 | 근거 | 해결 주체 |
|---|---|---|---|
| 1 | 모델의 배경 모양 암기 | 정렬 시 96%, 배경 제거 시 0% | 김태연(재학습) |
| 2 | 수신 지터 → 창 채움 → 점수 요동 | 채움 ≥ 95% 창 77%, < 80% 창 17% 발화 | 보드 시계 정렬 / 보드 내 추론 |
| 3 | 억제 간격이 경보 수를 결정 | 재현 65건 = 실제 65건 | 통합(S1) |
| 4 | '낙상 + 충격음' 규칙이 1초 창 하나를 봄 | 코드 결함 | 통합 |
| 5 | 노드별 창끝 차이 | 32.7% → 37.6%(+4.9%p) | 통합(새 모델 연동 때) |
| — | 두 종류 프레임 혼재(40~50%)·같은 프레임 반복(24~33%) | 점수와는 무상관. 움직임 지표는 3~4배 부풀림 | 김태연(펌웨어 필터) |

데이터 계약(보호 채널 0, 프레임 최댓값 1)은 정상이다. 반복 프레임은 수신 쪽 중복이 아니다. 보드가 새 CSI가 없을 때 직전 값을 다시 보낸 것이다.

## 4. 통합 쪽 확정 개선 (바로 적용 가능)
| # | 개선 | 효과 |
|---|---|---|
| A1 | **M1 단독 경보·M5 호출 중지**(`M1_ALERT_MODE=corroborated`) | 빈 방 경보 65건 → 0건. 남는 오경보는 M3 충격음 오탐 × M1 판정 상태로 추정 약 1.4회/시간이고, 음성 확인으로 거른다 |
| A2 | '낙상 + 충격음' 규칙을 1초 창 하나 대신 5회 중 3회로 | 지금 모델에선 효과 작음(38% → 35%). 설계 의도 복원 |
| A3 | 추론마다 점수·노드별 창 채움 기록(김태연 요청) | 모델 비교 근거 |
| A4 | 재현 도구를 합격 시험에 사용 | 새 모델을 넣기 전에 오경보 산출 |

**정할 것**: A1 기본값. 제안은 `corroborated`이고, RPi5에도 적용된다.

## 6. 같은 방에서 학습하면 되나 — 된다, 단 조건을 섞어야 한다
| 배경 모양 차이(1 − 코사인) | 노드 1 | 노드 2 | 노드 3 |
|---|---|---|---|
| 1분 안 프레임끼리 흔들림 | 0.0006 | 0.0025 | 0.0025 |
| 빈 방 113분 처음 대 끝 | 0.0001 | 0.0000 | 0.0001 |
| **같은 방 2시간 전(20:04)** | **0.06~0.07** | 0.01 | 0.02 |

- 아무것도 안 바뀐 빈 방은 그대로다. 그러나 같은 방이라도 사람·물건·문 상태가 다르면 **흔들림의 수십~백 배**가 바뀐다.
- 그래서 같은 방이라도 여러 날, 문·가구 상태, 사람 유무, 위치를 섞어 모으고, **학습에 안 쓴 날로 평가**한다.
- 실서비스는 역할을 나눈다.
  - 낙상 판별: 방과 무관한 '변화' 특징으로 일반화한다.
  - 배경: 설치한 집에서 라벨 없이 자동 보정한다.

## 7. 입력 설계 — '프레임 종류별로 고정 배경 빼기'가 가장 유망
빈 방에서 사람이 없을 때의 조용함·안정성으로 비교했다(낙상 반응은 미검증).

| 설계 | 잡음 바닥 | 판정 |
|---|---|---|
| 지금(원 모양) | 0.13~0.21 | 혼재로 3~4배 부풀려짐 |
| 배경만 빼기(종류 무시) | 0.11~0.19 | ✗ 두 종류 차이가 남아 움직임이 묻힘 |
| 한 종류만 남기고 변화량 | 0.043~0.048 | ○ 프레임 절반을 버림 |
| **종류별로 각자 배경 빼기** | **0.028~0.037** | ◎ 가장 조용·안정, 프레임 전부 사용, 어느 종류가 다수인지와 무관 |

## 8. 재학습할 때 — 노드와 데이터
- **노드별 판정 + 2개 이상 투표**가 좋다.
  - 빈 방 노드별 잡음은 서로 무관하다(상관 0.00~0.02).
  - 노드 하나가 튀는 확률 1%일 때, 두 노드가 동시에 튀는 확률은 0.08%다.
  - 지금처럼 노드를 한 텐서에 묶는 방식은 노드를 늘려도 효과가 없다.
- **모든 노드에 같이 오는 변화**(날·가구·공유기)는 투표로 못 막는다. 입력에서 배경을 빼야 한다.
- 먼 노드는 반응이 약하다(1.3배 대 가까운 노드 3.5배). 방 어디서든 가까운 노드가 2개 이상 되도록 배치한다.
- 데이터는 **양보다 다양성**이다.
  - 혼재 필터(≤ 15%)가 먼저다.
  - 비낙상(빈 방·앉기·눕기·물건 떨어뜨리기)도 낙상만큼 모은다.
  - 영상으로 라벨 시각을 확인한다.

## 9. 조건별 대안 요약
| 조건 | 대안(우선순위순) |
|---|---|
| 프레임 혼재 | 펌웨어 서명 고정(진행 중) · 공유기 ping 응답만 수용 · **허브에서 종류별 배경 빼기** · 혼재 증강 학습 · 공유기 설정(실험실만) |
| 배경 의존 | 입력에서 배경 제거 · 배경 바꿔 끼우기 증강 · 설치 후 자동 보정 · 라벨 없는 도메인 적응 · 이상 탐지 전환 |
| 수신 지터·빈 칸 | 보드 시계 + 굴림 오프셋 · 보드 내 추론 · 빈 칸 표시 채널 + 누락 증강 |
| 반복 프레임 | 새 프레임 비트로 빈 칸 처리 · 목표 50 Hz · 시각 붙은 새 프레임만 사용 |
| 노드 결합 | 노드별 판정 + 2개 이상 · 노드 누락 증강 · 거리 가중 |
| 판단 규칙 | 5초 평균 + 히스테리시스 · 음성 확인 · 소리(M3·M4) 보강 |
| 펌웨어(제조사 권장) | 수신 이득 고정(`phy_force_rx_gain`) — 아직 없음, 제안 |

## 10. 재학습 없이 할 수 있는 것 — 급변 감지기
| 하려는 것 | 재학습 |
|---|---|
| **급변 감지기**: 종류별 배경을 뺀 신호가 평소보다 크게 오르고, 노드 2개 이상이 동시에 오르면, 5초 모아서 판단 | **필요 없음**(계산 규칙, RPi5 부담 거의 없음) |
| 이 신호를 지금 M1 모델에 입력 | 불가(점수 0.38 한 값) |
| 낙상만 골라내는 모델 | 재학습(N_pose 입력 변경) |

- 급변 감지기는 '낙상'이 아니라 '큰 움직임'을 잡는다.
- '크게 움직인 뒤 조용 + 방에 새 물체가 남음(누워 있음)' 규칙을 더할 수 있다. 다만 빨리 앉아서 가만히 있는 경우와 구분이 어렵다 → **음성 확인·소리와 겹쳐** 쓴다.
- 기준값은 테스트 한 번으로 정하지 말고 여러 번 반복해서 확인한다.

## 11. 다음 단계 — 5분 사람 테스트
- **준비**: 노트북 수신(`start_laptop.ps1`) + CSI 기록기 + 휴대폰 영상(노트북 화면 시계가 같이 찍히게)
- **순서**(시작 시각 메모)
  1. 빈 방 1분
  2. 걷기 30초
  3. 앉기·일어서기 3회
  4. 눕기
  5. 매트 위 모의 낙상 2~3회
  6. 누운 채 1분
  7. 퇴장
- **볼 것**
  - 동작마다 급변 신호가 빈 방 최대(1.65배)를 넘어 **2배 이상** 오르는지
  - 누운 채로 있을 때 기준선으로 돌아오는지
  - 지금 M1 점수가 모의 낙상 때 달라지는지
- **판정**
  - 오르면: 급변 감지기를 A1의 보강 신호로 추가한다(로컬 검증 → 김태연 합의 → 운영 반영. 새 Redis 키가 필요하면 별도 확인). 김태연 새 모델 입력도 이 방식으로 제안한다.
  - 안 오르면: 급변 감지기를 버리고, M1은 새 모델까지 기록 전용으로 둔다.

## 11-1. 재설계 방향 (상세: `M1_REDESIGN_PROPOSAL_20260928.md`)
- 잡음 줄이기·모아서 판단·데이터 추가는 모두 필요하지만 충분하지 않다. 세기만 있는 1안테나 CSI는 '큰 움직임'에 강하고 '낙상 대 빨리 앉기' 구분에 약하다.
- 정확도를 올리는 것은 네 가지다.
  - 신호 품질: 한 종류 프레임, 수신 이득 고정, `frame_peak`, 100 Hz 검토
  - '변화' 입력
  - **사건 단위 판단**: 급변 → 2개 노드 이상 → 사건 분류 → 결합
  - **소리·음성 결합**: CSI 사건 + 충격음 ±3 s면 우연 겹침 약 0.4회/시간 [추정]
- 세 가지 구성
  - A: N_pose + 입력 교체
  - B: 허브 사건 파이프라인
  - C: CSI는 움직임만, 낙상 확정은 소리·음성
- **발표 안전판은 C. 본선은 A 또는 B이고, 김태연 0단계 벤치 결과로 정한다.**

## 12. 결정 필요
1. A1 기본값(`corroborated` 제안)
2. 5분 테스트 일정
3. 새 모델 합격선
   - 학습에 안 쓴 날의 빈 방 1시간 이상에서 판정 시작 **시간당 0.1회 이하**
   - 배경 제거·시간 섞기 창에서 점수가 내려갈 것
   - 혼재 ≤ 15%, 창 채움 ≥ 95%
4. 허브 규칙: 노드별 판정 → 2개 이상 → 5초 히스테리시스 → 음성 확인, `min_nodes`

## 13. 김태연 님 보고와의 정정
- "장치 시각 2.1 s 건너뜀"(09-23 통합 문서)은 틀렸다. 패킷 1개가 2.1 s 늦게 도착한 것이다(김태연 설명이 맞음).
- 통합 쪽 초안 수치(120초 기준 7.6%, 약 2배 등)는 113분 기준 수치로 바로잡았다.
