## 3. RPi5 실측 — M1

| 조건 | M1 1회 추론 지연 |
|---|---|

### ★ 확인된 문제 — 실 파이프라인에서 M1이 입력 창을 받지 못함 (통합 쪽 원인)

- 새 모델 적용 후 30초 관찰에서 `fall_score`가 150회 모두 **0.5959262**였습니다.
  이 값은 모델에 **전부 0인 입력**을 넣었을 때의 출력(0.5959263)과 같습니다. 부하 비교 측정 2회도 같았습니다.
- 오전 기본값 측정(옛 1노드 모델)도 점수가 한 값(0 입력 출력)으로 고정이었습니다.
- 원인은 **통합 코드의 처리 구조**입니다. 모델 문제가 아닙니다.
  CSI 루프가 패킷마다(3노드 × 100 Hz = 초당 300회) M1을 호출해 처리량이 입력을 못 따라감 →
  최신 위치로 건너뜀 → 노드 간격 150 ms 초과로 버퍼 리셋 → 100프레임 창이 끝내 차지 않음 → 슬롯 전부 0.
- 0 입력 점수 0.596은 임계값 0.80보다 낮아 **오경보는 나지 않았지만, 낙상도 감지할 수 없는 상태**입니다.
- 통합 쪽에서 "M1을 노드당 N프레임마다 실행 + 창이 차지 않으면 추론 생략"으로 고칠 예정입니다(노진산).

### 확인 부탁드리는 것

1. **학습 때 창을 몇 프레임 간격으로 밀었는지(stride/hop)** 알려주세요. 통합 쪽 추론 간격(후보 10프레임 = 노드당 10 Hz)을 정하는 데 씁니다.
2. 창이 일부만 찬 노드는 0 패딩으로 두는 게 맞는지, 아니면 그 노드가 준비될 때까지 추론을 미루는 게 맞는지 의견 부탁드립니다.
   (지금 계약상 미연결 노드는 0 패딩)
3. 새 모델의 **전부 0 입력 출력이 0.596**입니다. 노드가 전부 끊긴 경우를 통합 쪽에서 별도로 처리하려고 하니, 이 값이 의미 있는 기준인지 참고로만 알려주세요.

## 5. M2 현황

- RPi5에서 실제로 돌고 있는 M2는 **미학습 스텁**(인계 파일 아님)이며 입력과 무관하게 **심박 118.3·호흡 24.1**을 냅니다.
- 위험도 규칙의 심박 경고 상한이 100 bpm이라 이 값이 **바이탈 경고를 계속 만듭니다**(M2만 켠 측정에서 버퍼가 찬 구간 경고 1,347건, 빈 구간 정상 2,259건).
  통합 쪽에서 M2를 끄거나 스텁을 빼는 방향으로 정리할 예정입니다.
- 인계 스펙트럼 추정기(30 s 창, 노드별 배열 출력)는 배선 방식을 상의한 뒤 연결합니다.

### 요청

- 10월 1순위(펌웨어에서 정규화 전 피크값 전송)는 **788 B UDP 패킷 규격이 바뀌는 일**이라 sensing 파서도 함께 바뀝니다.
  필드 위치·형식을 정하시면 먼저 공유 부탁드립니다. 현재 `struct.Struct("<4sBBHIIhH192f")`이고 예약 필드는
  uint8 1개(offset 5)·uint16 1개(offset 18)뿐이라, float32(4바이트)를 넣으려면 패킷 길이나 형식이 바뀝니다.
- M2 존폐 판정 결과가 나오면 공유 부탁드립니다. M5 입력 구성(M1·M3·M4만 쓸지)이 그에 따라 바뀝니다.
