## 1. 결론
- 지금 M1 인계 모델(`m1_wifi_pose_onnx`, 9/16 3노드 학습)은 **다른 날·다른 배치의 빈 방에서 학습 때 빈 방(1.3%)보다 6~60배 자주 발화**한다. 어떤 입력 조립으로도 운영할 수 없는 수준이다(2절).
  - 빈 방 113분 기준(2-0절)
    - 학습 로더와 같은 조립: 1초 창 32.7% 발화
    - 지금 통합 코드: 37.6%
    - 빈 칸 없는 조립(보드 시계): 96.1%. 김태연 분석 98%와 일치
- 모델은 **움직임(시간 변화)을 거의 보지 않는다.** 노드 1·3의 정적인 채널 모양과 0 채움 양에 반응한다(2-2절). 새 날·새 배치에서 정적 모양이 바뀌면 점수가 통째로 올라간다(세션 암기).
- 09-23 노트북 실험의 "규칙 경보 65건(시간당 약 35건)"은 **오경보율이 아니다.** 5회 중 3회 판정은 시간당 수백 번 시작됐고, 재발동 억제 간격(90초)이 허용하는 최대치(시간당 40건)에 가깝게 경보가 났다.
- 원인
  1. **데이터**: 두 종류 CSI 프레임이 무작위로 섞임(혼재 36~49%, 김태연)
  2. **모델**: 9/16 한 세션의 정적 채널 모양을 외움
  3. **통합(일부)**: 노드별로 창끝이 달라 학습 로더보다 발화가 +4.9%p다(113분 기준, 2-3절). 고치더라도 모델 문제는 남는다.
- 그래서 통합 쪽에서는 **모델을 고칠 수 없다.** 새 모델(N_pose, 보드 내 추론)이 합격선을 넘기 전까지 **M1 단독으로는 경보가 나가지 않게 막고**, 새 모델을 받을 준비를 하는 것이 대책이다.

| 다른 날 빈 방 | **학습에 쓰지 않은 날**의 빈 방 1시간 이상에서 5회 중 3회 판정 시작 **시간당 0.1회 이하**(1주일에 약 17회 이하) | 허브 점수 CSV 또는 검증 기록기 |
| 일상 동작 | 앉기·눕기·물건 줍기 시나리오에서 오판정 없음 | 영상 시나리오 시험 |
| 낙상 감지 | 사건 단위 재현율(유형별) | 영상 시나리오 시험(낙상 5유형) |
| 입력 | 혼재 ≤ 15%, 창 채움 ≥ 95%, 직전 반복 프레임 비율 기록(학습·운영 같은 수준) | `verify_collect`, 기록기, `m1_false_alarm_analysis.py` |
| 모델 민감도 | 시간 순서 섞기·정적 창에서 점수가 **내려가야** 함(지금 모델은 오히려 오름) | `m1_false_alarm_analysis.py --sens` |

- 합격 후에는 M1 단독 경보를 켠다. 이때 오판정은 **음성 확인**("괜찮으세요?")으로 한 번 더 거른다.
  무응답이면 알림. 재실 중 오판정은 여기서 걸러진다.
- 빈 집 오판정이 남으면 **최근 활동 조건**을 검토한다: 낙상 직전 일정 시간 안에 움직임·소리·말소리가 있었을 때만 인정.
  - 쓰러진 뒤 조용한 상황을 놓치지 않도록, 확인 구간은 사건 **이전**을 본다.
  - 프레임 혼재가 풀려야 CSI 움직임 지표를 쓸 수 있다(혼재 시 1초 창 흔들림이 사람 유무와 무관하게 0.2로 일정).
