# N_pose v1 보드 모델 — WiFall 검증 세트로 본 허브 규칙 (2026-10-05)

작성: 노진산(통합).

## 사용 자료
- 데이터: `wifall_val_ID8_ID9.zip`(김태연 제공) → `data/m1_eval_wifall/`(Git 제외)
  - 공개 데이터 WiFall의 사람 ID8·ID9, 64클립(낙상 32 · 헷갈리는 동작 24 · 일상 8)
  - 50 Hz, 클립당 약 3초. N_pose 수집 CSV 형식(stream_id, node_id, seq_num, ts_ms, rssi, fresh, sig_mode, frame_peak, raw_0..63)
  - 학습은 ID0~7. 단 이 세트로 에폭·시드를 골랐으므로 완전한 시험 세트는 아니다(README).
- 모델: 보드에 올라간 v1(`MODEL_VERSION_ID 1`) = N_pose `rebuild/model` 브랜치 `runs/pretrain/20261005_wifall_raw_s1`
- 수치: 같은 런 폴더의 `clip_eval.json`(김태연 `model/clip_eval.py` 출력)
  - 보드와 비트 단위로 같은 int8 계산이다.
  - 2초 창, 0.2초 간격, 창 안 새 프레임 비율 ≥ 0.9인 창만 쓴다.
  - 같은 세트를 다른 시드로 학습한 s2·s3도 같이 봤다.

## 결과 — 모델은 낙상을 구분하는데, 허브 규칙이 놓친다

| 규칙(노드 1개) | v1(s1) 낙상 | v1 비낙상 | s2 낙상 / 비낙상 | s3 낙상 / 비낙상 |
|---|---|---|---|---|
| **지금: 5회 중 3회 ≥ 0.8** | **7/32** | 1/32 | 11/32 · 0/32 | 12/32 · 6/32 |
| 5회 중 2회 ≥ 0.8 | 21/32 | 4/32 | 19/32 · 2/32 | 24/32 · 9/32 |
| 1회 ≥ 0.8 | 29/32 | 8/32 | 28/32 · 5/32 | 31/32 · 17/32 |
| **1회 ≥ 0.9** | **25/32** | **2/32** | 24/32 · 1/32 | 28/32 · 10/32 |
| 1회 ≥ 0.95 | 14/32 | 0/32 | 17/32 · 1/32 | 16/32 · 0/32 |

- 클립 AUC: v1 0.948, s2 0.937, s3 0.894
- 낙상 클립에서 0.8 이상 창의 개수(v1): 0개 3, 1개 8, 2개 14, 3개 4, 4개 3 → **대부분 1~2개**다. "5회 중 3회"는 낙상 신호보다 길다.
- v1 기준으로는 **1회 ≥ 0.9가 2/5 @0.8보다 낙상은 더 잡고(25 대 21) 오판은 적다(2 대 4).**
- 비낙상 오판은 대부분 헷갈리는 동작(점프·앉기 등)에서 났다(v1 일상 동작 0/8).

## 주의 — 이 숫자만으로 규칙을 정하면 안 되는 이유
1. **클립이 3초라 판정에 쓸 수 있는 창이 4~6개뿐이다.** 실제 연속 스트림에서는 낙상 앞뒤로 창이 더 있어, "5회 중 3회"가 클립 평가보다 잘 맞을 수 있다. → 실제 방에서 모의 낙상(영상 시험)을 보드 점수로 다시 잰다.
2. **빈 방·일상 오경보는 이 세트로 잴 수 없다.** 1회 ≥ 0.9는 창 하나만 튀어도 경보다. 빈 방 시간당 횟수를 실측해야 한다.
3. 시드에 따라 차이가 크다(s3는 비낙상 오판이 많음). 지금 보드는 s1이다.
4. 노드 4·5처럼 새 프레임 비율이 낮은 노드는 창이 판정에서 빠지므로, 어떤 규칙이든 그 노드 방향의 감지가 약하다(GPU 검증 1단계 참고).

## 통합 쪽에서 바꾼 것 (기본 동작은 그대로)
- 보드 규칙을 ONNX 경로와 분리해 환경변수로 바꿀 수 있게 했다. 재빌드 없이 재시작만 하면 된다.
  - `M1_BOARD_THRESHOLD`(기본 0.80), `M1_BOARD_K`(3), `M1_BOARD_N`(5), `M1_BOARD_MIN_NODES`(1), `M1_BOARD_MIN_COVERAGE`(0.9)
- `scripts/dev/npose_quality.py`
  - 빈 방 실측에서 규칙 후보 8개의 허브 경보 횟수(시간당)를 한 번에 낸다: 3/5·2/5·1/5 @0.8, 1/5·2/5 @0.9, 1/5 @0.95, 노드 2개 조건
  - 원 점수를 `*_rows.npz`로 남겨 다른 규칙으로도 다시 계산할 수 있다.

## 제안 순서
1. **빈 방 30분 이상**
   ```bash
   python scripts/dev/npose_quality.py --seconds 1800 --label empty_room --out reports/laptop/val_20261005/npose_empty.json
   ```
   → 규칙별 빈 방 오경보(시간당)를 잰다.
2. **실제 방 모의 낙상·일상 동작(영상 시험)**: 모델별 출력 기록기의 `m1_node_score.csv`(보드 점수)로 같은 규칙 후보의 감지율을 잰다. 실제 연속 스트림 기준이다.
3. WiFall 감지율, 빈 방 오경보, 실제 방 감지율 세 가지로 규칙을 고른다. 후보는 1회 ≥ 0.9 또는 2/5 @0.8이다. 김태연 `hub/receiver.py`와 기본값을 함께 바꾼다.
4. 김태연 님께: 창 단위 재평가가 필요하면 `model/clip_eval.py --threshold 0.9 --k 1`로 바로 잴 수 있다. 통합 PC에는 TensorFlow가 없어 클립별 결과(`clip_eval.json`)로만 계산했다.
