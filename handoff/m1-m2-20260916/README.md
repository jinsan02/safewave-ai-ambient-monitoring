## M1 — 드롭인입니다. 바꿀 건 임계값 하나뿐입니다

### 1. 파일 배치

```bash
cp handoff/m1-m2-20260916/m1_wifi_pose.onnx \
   volumes/models/m1_wifi_pose_onnx/m1_wifi_pose.onnx
```

`.env` 의 `FALL_DETECTION_MODEL=m1_wifi_pose_onnx` 가 가리키는 디렉터리입니다.
**파일명을 바꾸지 마세요** — 로더가 `m1_wifi_pose.onnx` 를 찾습니다.
다른 이름이면 조용히 `_infer_fallback`(분산 기반 가짜 점수)으로 넘어갑니다.

### 2. 임계값 `0.7` → `0.80`

`ai/experts/m1_wifi_pose.py` 의 `_infer_onnx` / `_infer_fallback` 두 군데입니다.
환경변수로 빼두면 재빌드 없이 조정할 수 있어 아래 형태를 권합니다.

```python
FALL_THRESHOLD = float(os.getenv("M1_FALL_THRESHOLD", "0.80"))
...
return {"fall_score": score, "fall_detected": score >= FALL_THRESHOLD, ...}
```

근거는 `M1_HANDOFF.md` §3 입니다. 요약하면, 검증셋 양성 비율은 24.35% 인데
실제 운영에서 낙상 창 비율은 10만분의 1 수준이라 검증셋 f1 최적점은 배포에서
오경보로 무너집니다. 그래서 f1 이 아니라 **빈 방 발화 대비 우도비**로 골랐습니다.

| 임계값 | 낙상 재현율 | 빈 방 발화 | 우도비 |
|---|---|---|---|
| 0.30 | 0.853 | 92.4% | **0.92** |
| 0.50 | 0.747 | 51.7% | 1.44 |
| 0.70 | 0.564 | 17.6% | 3.20 |
| **0.80** | **0.480** | **1.3%** | **38.08** |

0.30 에서는 우도비가 1 미만입니다. 낙상일 때보다 빈 방일 때 더 자주 울린다는
뜻이라, 그 임계값의 발화는 낙상의 증거가 아니라 반증입니다.

### 3. 그 외에는 변경 없음

`ai/main.py` 의 5노드 슬롯 조립과 이 모델의 입력 계약이 **정확히 일치**합니다.

```
m1_input = np.stack(_slots, axis=0)[None, ...]   # (1, 5, 64, 100)
_slots[_n - 1] = ...                             # node_id N → 슬롯 N-1
```

- 입력 `csi_data` `(1, 5, 64, 100)` float32 — 지금 만들어 넣는 것 그대로
- 4차원이라 `_preprocess` 를 통과합니다
- `M1_MAX_NODES` 는 **5 그대로** 두세요
- 출력 `fall_score` `(1, 1)` — **이미 0~1 확률입니다**

### ★ 출력에 시그모이드를 적용하지 마세요

현재 `_infer_onnx` 가 시그모이드 없이 `np.clip(score, 0, 1)` 로 받고 있어서,
**그래프 안에 Sigmoid 를 넣어 내보냈습니다.** 지금 코드 그대로면 맞습니다.

만약 나중에 `_infer_onnx` 에 시그모이드를 추가하시면 **이 파일의 것을 빼야 합니다**
(이중 적용되면 점수가 0.5~0.73 구간에 뭉개져 임계값이 무의미해집니다).
둘 중 한 곳에서만 하면 됩니다. 빼야 할 때 알려주시면 다시 내보내드리겠습니다.

## ★★ 유의사항

### 실제 학습은 3노드입니다

9/14 합의는 `(1,5,64,100)` 5노드였으나, 현장에 외장안테나 모델 보드는 있었지만
**안테나가 없어서** 내장안테나 3대로 수집·학습했습니다.

이 파일은 **3노드 모델의 첫 conv 가중치를 5채널로 0 패딩**한 것입니다.

```
슬롯 0 ← 노드 1   학습된 채널
슬롯 1 ← 노드 2   학습된 채널
슬롯 2 ← 노드 3   학습된 채널
슬롯 3 ← 가중치 0 (무시됨)
슬롯 4 ← 가중치 0 (무시됨)
```

슬롯 3·4 에는 무엇이 들어와도 점수가 바뀌지 않습니다 — 최대 ±459 크기의 잡음을
넣고 5회 비교해 `max|diff| = 0.000e+00` 으로 확인했습니다. 노드 4·5 를 실제로
쓰려면 **재학습이 필요합니다.** 안테나 확보되면 10월에 5노드 재수집·재학습해서
교체하겠습니다. 그때도 입출력 계약은 그대로입니다.

### 성능 — 절반만 잡습니다

검증 924창(양성 비율 0.2435) 기준, PR-AUC **0.436** (베이스라인 대비 1.79배).
임계값 0.80 에서 **낙상 재현율 0.480** (108/225, 95% 신뢰구간 0.416~0.545),
빈 방 오탐 1.3% (3/238, 신뢰구간 0.4~3.6%), 걷기 오탐 0.0%.

**하는 일:** 걷기 같은 일상 동작과 낙상은 구분합니다(8/2 버전 걷기 오탐 32% → 0.0%).
**못 하는 일:** 의자에 앉기·바닥에 앉기 같은 낙상 유사 하강 동작은 구분하지 못합니다.
빠르게 앉는 동작의 분리는 M5 규칙으로 처리할 부분으로 남겼습니다.

시드가 고정돼 있지 않아 동일 설정 재학습 시 PR-AUC 가 0.41~0.47 사이에서 움직입니다.
빈 방 발화율은 편차가 더 커서 @0.70 기준 1.7%~17.6% 까지 벌어졌습니다.

### M5 에는 이진 판정 말고 점수를 넘겨주세요

`fall_detected` 대신 `fall_score`(0~1) 를 그대로 넘기시면 M5 가 확률로 가중할 수
있습니다. 위 우도비 표를 같이 쓰시면 됩니다. 0.80 은 M1 단독 동작용 기본값입니다.

### `scripts/test_m3_m4_experts.py` 는 이 모델로 실패합니다

그 스크립트가 1차원 더미(512 샘플)를 넘기는데, `_preprocess` 의 비-4차원 경로가
`(1, 1, n_ch, n_t)` 를 만들어서 노드 축이 1 이 됩니다. 5채널 모델과 맞지 않습니다.
실제 파이프라인은 `main.py` 가 4차원으로 조립해 넘기므로 영향이 없습니다.
테스트를 돌리시려면 더미를 `np.zeros((1,5,64,100), np.float32)` 로 바꿔주세요.

## M2 — 드롭인이 아닙니다. 배선은 상의가 필요합니다

**이건 학습된 모델이 아닙니다.** 수집 데이터에서 호흡·심박 신호가 검출되지 않아
학습시킬 것이 없었습니다. 대조군이 역전돼 있습니다 — 빈 방이 사람 활동보다
게이트를 더 자주 통과합니다(호흡 69.1% vs 56.2%, 심박 95.7% vs 89.6%).

그래서 학습 모델 대신 **주파수 분석기를 고정 가중치로 ONNX 에 박아서** 냈습니다.
목적은 성능이 아니라 **입출력 계약 고정**입니다. 전체측정에서 M2 자리가 비지 않게
하고, 10월에 진짜 모델이 나오면 교체만 하면 되도록 한 것입니다.
**출력 bpm 값은 신뢰하지 마세요.**

현재 `ai/experts/m2_frenel_vital.py` 와 맞지 않는 부분이 둘 있습니다:

1. **입력 창 길이** — 이 모델은 `(1, 3, 64, 3000)`, 즉 **30초** 창입니다.
   현재 M2 버퍼는 프레임별 64채널 평균 스칼라를 쌓는 1차원 시계열이라 구조가 다릅니다.
2. **출력 키** — 이 모델은 노드별 배열 5종(`resp_bpm`, `heart_bpm`, 각 SNR,
   `resp_spectrum`)을 냅니다. 그쪽은 `heart_rate` / `breathing_rate` 스칼라를 기대합니다.

`m2_runtime.py` 가 전처리부터 게이트까지 단독으로 돌아가니 참고하시고,
어떻게 붙일지는 상의하고 정하는 게 좋겠습니다. 어차피 값이 무의미한 단계라
무리해서 꽂을 이유는 없습니다.

### 왜 신호가 없는지 — 미검증 가설

ESP 가 프레임마다 진폭을 피크 1.0 으로 정규화하면서 **배율을 버리고 있습니다**
(34세션 17,034프레임 전부 피크가 정확히 1.000000). 피크 정규화는 공통모드 진폭
변조를 수학적으로 정확히 0 으로 만듭니다(차동 변조는 통과).

호흡은 진폭 변조, 낙상은 진폭 급변이 주요 단서라, 이 전처리가 M2 의 신호 부재와
M1 의 빈 방 오탐을 **동시에** 설명할 가능성이 있습니다. 아직 가설입니다 —
"호흡이 공통모드라 지워졌다" 와 "애초에 CSI 에 호흡이 실리지 않았다" 를 지금
데이터로는 가릴 수 없습니다. **단정해서 인용하지 마세요.**

가르는 방법은 쌉니다. 펌웨어에서 정규화 전 프레임 피크값을 **프레임당 float 하나만**
더 보내고 1분 녹화하면 됩니다. 10월 1순위로 잡아뒀습니다.
