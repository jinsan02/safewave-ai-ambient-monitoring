## 1. 베이스 → 현재 변경점

### 1-1. 입력 계약이 바뀌었다 — 단일노드에서 노드축 조기융합으로

| | 이전 (베이스) | 현재 |
|---|---|---|
| 입력 텐서 | `(1, 1, 64, 100)` | **`(1, N, 64, 100)`** — 이번 산출물은 **N = 3** |
| 노드 처리 | 노드마다 따로 추론 | **노드축을 첫 conv 의 입력채널로 조기융합** |
| 부반송파 | 64 | 64 (변동 없음) |
| 프레임 | 100 (1초 @ 100 Hz) | 100 (변동 없음) |

노드는 **채널축**으로 쌓는다. 부반송파축에 이어붙이는 방식(레거시 `3 × 64 = 192`)이
**아니다.** 192 concat 은 금지다.

### 1-2. `dataset.py` 전면 재작성 — 노드 간 정렬 기준을 바꿨다

**`ts_ms` 는 보드마다 다른 장치 시계다. 노드를 교차 정렬하는 데 쓰면 안 된다.**
보드별로 값이 다르고 32비트에서 랩어라운드한다. 이걸로 노드를 맞추면 노드들이
서로 어긋난 채로 한 창에 들어간다 — **추론이 실패하지 않고 조용히 틀린 입력이 된다.**

정렬은 **`stream_id` 앞부분의 epoch**(= rp5 수신 시각)로 한다. 이것이 노드 간
**유일한 공통 시계**다. 형식은 `"<epoch_ms>-<seq>"`, 예: `"1781165460004-0"`.

```
행마다 epoch = stream_id 앞부분
  → 세션 전체를 공통 100 Hz epoch 그리드로 (10 ms 간격)
  → 노드별 프레임을 최근접 슬롯(±5 ms)에 매핑, 겹치면 더 가까운 쪽
  → 비어 있는 (노드, 슬롯) 은 0 으로 패딩
  → 노드·프레임별 peak 정규화 + guard 서브캐리어 0
  → 창 100프레임 → (1, 3, 64, 100)
```

### 1-3. 데이터를 본 수집분으로 교체

- 본 수집 **34 세션 / 낙상 48 건** (3노드, 100 Hz, 2026-09-16)
- 학습에 쓴 라벨: `data/labels_split.csv` (27 세션)
- 하드 네거티브 7 세션은 **학습에서 제외**했다 (이유는 §4 마지막 항목)

### 1-4. 선정 지표를 `fall_recall` 에서 `pr_auc` 로 교체

`fall_recall` 을 기준으로 best 를 고르면 **전부 양성이라고 찍는 퇴화 모델이 1등으로 뽑힌다**
(recall 1.000, precision 0.244). 실제로 그렇게 뽑혔다. `pr_auc` 는 precision 을 같이
보기 때문에 이 퇴화를 걸러낸다.

## 3. 구동 코드

**`scripts/m1_runtime.py`** — 전처리부터 판정까지 한 파일. 의존성은 `numpy` + `onnxruntime`.

```python
from m1_runtime import M1Runtime
rt = M1Runtime("models/m1_base_3node_20260916.onnx", threshold=0.80)
res = rt.predict_from_packets(packets)     # 실시간
res = rt.predict_from_csv("csi_....csv")   # 파일
```

```bash
python scripts/m1_runtime.py --csv <파일> --threshold 0.80
```

> **검증됨:** 이 파일의 전처리 결과가 학습 로더(`src/m1_fall/dataset.py`)와
> **비트 단위로 동일**하다. 같은 CSV 로 그리드 슬롯 수·시각·정규화 프레임·결측
> 마스크를 전부 대조했고 차이 0이었다.

### 입력 규격

| 방식 | 함수 | 형식 |
|---|---|---|
| 패킷 리스트 (실시간) | `predict_from_packets(packets)` | `[{"stream_id": "1781165460004-0", "node_id": 1, "raw": [64개 float]}, ...]` |
| 수집 CSV | `predict_from_csv(path)` | 컬럼 `stream_id, node_id, ts_ms, raw_0..raw_63` |
| 완성된 텐서 | `predict_tensor(x)` | `(1, 3, 64, 100)` float32 |

- `stream_id` 는 **`"<epoch_ms>-<seq>"`** 형식이어야 한다. 노드 정렬에 쓰는 유일한 시계다.
- `node_id` 는 **1 ~ 3** 정수. 범위를 벗어나면 예외를 던진다.
- `ts_ms` 는 읽기만 하고 **정렬에는 쓰지 않는다.** 패킷 입력에서는 없어도 된다.
- 최소 100 프레임(1초)이 그리드에 쌓여야 추론한다. 부족하면 예외.

### 출력 규격

| 키 | 타입 | 의미 |
|---|---|---|
| `score` | float | 0~1 낙상 확률 (sigmoid 적용 후) |
| `logit` | float | sigmoid 적용 전 원시 로짓 |
| `fired` | bool | `score >= threshold` |
| `threshold` | float | 판정에 쓴 임계값 |
| `n_nodes` | int | 모델이 기대하는 노드 수 (ONNX 에서 읽는다) |
| `node_coverage` | list[float] | 노드별 실제 프레임이 채워진 비율 0~1 |
| `coverage_mean` | float | 위 평균 — 낮으면 수집·동기 문제를 먼저 의심 |
| `window_epoch_ms` | [int, int] | 창의 첫/마지막 그리드 슬롯 시각 |
| `n_windows` | int | 만들어진 창 개수 |
| `windows` | list[dict] | 창별 결과 (CSV 입력에서만) |

**분모 (모집단):** 검증셋 924창 = 낙상 라벨 **225창** · 빈 방 **238창**(세션 `1356`+`1358`)
· 나머지 461창. `recall` 은 225창 기준, `빈 방 발화` 는 238창 기준이다.

**우도비**는 `낙상 재현율 / 빈 방 발화율` 이다. **1 미만이면 그 임계값의 발화는
낙상의 증거가 되지 못한다** — 빈 방이 낙상보다 더 자주 울린다는 뜻이기 때문이다.
0.10~0.35 구간이 전부 1 미만이다. 이전 권고값이던 0.30 은 **0.92** 로, 발화가
낙상을 시사하지 못하는 구간이었다.

**권고 임계값: `0.80`** (recall 0.480 / precision 0.545 / f1 0.511 / 빈 방 **3/238 = 1.3%** / **우도비 38.08**)

### 왜 f1 이 아니라 우도비로 골랐는가

**검증셋 양성 비율은 24.35% 지만, 실제 운영에서 낙상 창 비율은 10만분의 1 수준이다.**
이 사전확률 차이 때문에 **검증셋 f1 최적점은 배포에서 오경보로 무너진다.**
검증셋에서 오경보 1건이 정답 1건과 비슷한 무게로 취급되는 반면, 운영에서는
음성 창이 10만 배 많아 같은 오탐률이 경보의 대부분을 차지하게 된다.

그래서 f1 이 아니라 우도비로 고른다:

| | f1 | 우도비 | 빈 방 발화 | 낙상 재현율 |
|---|---:|---:|---:|---:|
| 0.75 | 0.503 | 7.67 | 16/238 = 6.7% | 116/225 = 0.516 |
| **0.80** | **0.511** | **38.08** | **3/238 = 1.3%** | **108/225 = 0.480** |

f1 은 0.503 → 0.511 로 사실상 차이가 없지만 **우도비는 7.67 → 38.08 로 5배**다.
재현율은 0.516 → 0.480 으로 0.036 만 내주고 빈 방 발화를 1/5 로 줄인다.

> **표본이 작다는 점은 알고 쓰라.** @0.80 의 빈 방 발화 1.3% 는 **238창 중 3창**이다.
> Wilson 95% 신뢰구간은 **0.4% ~ 3.6%** 로 아직 넓다. 빈 방 세션이 2개(`1356`,`1358`)
> 뿐이라 세션 간 변동도 반영돼 있지 않다. 신뢰구간은 §3 아래 표 참조.

### M5 연동 권고 — 이진 판정으로 쓰지 마라

**M1 출력을 `fired` 같은 이진 판정으로 받지 말고, 로짓 또는 시그모이드 확률을
그대로 M5 에 넘겨라.** 임계값을 M1 쪽에서 적용하면 그 순간 정보가 1비트로 줄고,
M5 는 "0.81 과 0.99 중 무엇이었는지"를 알 수 없게 된다.

- **넘길 값**: `logit` (원시) 또는 `score` (sigmoid 적용, 0~1). 둘 중 하나면 된다.
- **함께 쓸 것**: 위 §3 우도비 표. 점수 구간마다 우도비가 크게 다르므로
  (0.30 에서 0.92, 0.80 에서 38.08) **M5 가 확률 가중으로 쓰는 편이 낫다.**
  같은 "발화"라도 0.80 대 발화와 0.30 대 발화는 증거로서의 무게가 40배 차이난다.
- **임계값 0.80 은 M1 이 단독으로 동작해야 할 때의 기본값이다.**
  M5 와 연동한다면 `scripts/m1_runtime.py` 의 `threshold` 를 낮게 두거나
  `fired` 를 무시하고 `score` 만 읽어라 — 점수 자체는 임계값에 영향받지 않는다.

```python
res = rt.predict_from_packets(packets)
m5_input = {"m1_score": res["score"], "m1_logit": res["logit"],
            "m1_coverage": res["coverage_mean"]}   # fired 는 넘기지 않는다
```

> `coverage_mean` 도 같이 넘기는 것을 권한다. 노드 커버리지가 낮은 창은 입력이
> 0 패딩으로 채워진 것이라 점수 신뢰도가 떨어진다. M5 가 이걸 감가 요인으로 쓸 수 있다.

## 3-A. 통합 레포 배포용 ONNX (`jinsan02/safewave-ai-ambient-monitoring`)

통합 레포에 넣을 파일은 **별도로 하나 더** 있다. §2 의 기본 산출물과 **의도적으로 다르다.**
둘 다 유지하며 섞어 쓰지 마라.

| | **기본 산출물** | **통합 레포 배포용** |
|---|---|---|
| 경로 | `models/m1_base_3node_20260916.onnx` | **`models/integration/m1_wifi_pose.onnx`** |
| 입력 | `csi_data` `[batch, **3**, 64, 100]` | `csi_data` `[batch, **5**, 64, 100]` |
| 출력 이름 | `fall_logit` | **`fall_score`** |
| 출력 값 | **pre-sigmoid 로짓** (범위 제한 없음) | **0~1 확률** (sigmoid 적용 후) |
| 그래프 내 Sigmoid | **없음** | **있음 (1개)** |
| opset / 동적 축 | 17 / batch 만 | 17 / batch 만 |
| 호출 쪽에서 sigmoid | **해야 함** | **하면 안 됨** (이중 적용) |
| 생성 스크립트 | `src/m1_fall/export.py` | `scripts/export_integration_onnx.py` |

### 왜 여기에는 Sigmoid 를 넣었는가

이 레포의 기본 규칙은 **"ONNX 에 Sigmoid 를 넣지 마라"** 다 (`CLAUDE.md` 규칙 2).
**통합 레포 배포용은 그 규칙의 의도적 예외다.**

통합 레포의 `ai/experts/m1_wifi_pose.py` 는 이렇게 받는다:

```python
score = float(output_arr.reshape(-1)[0])
score = np.clip(score, 0.0, 1.0)
```

**sigmoid 를 적용하지 않고 로짓을 그대로 자른다.** 그래프에 sigmoid 가 없으면
음수 로짓은 전부 `0.0`, 양수는 `1.0` 근처로 뭉개져 **임계값이 무의미해진다.**
그래서 이 파일에는 넣어야 한다.

> ⚠️ **나중에 "규칙 2 위반"으로 보고 빼지 마라.** 빼면 조용히 망가진다.
> 반대로, 통합 레포가 나중에 sigmoid 를 적용하도록 바뀌면 **이 파일의 sigmoid 를
> 빼야 한다** — 그때는 이중 적용이 된다. 둘 중 한 곳에서만 해야 한다.

### 채널 3·4 는 가중치가 0 이다 — 무엇이 들어와도 결과가 같다

이 모델은 3노드로 학습한 것을 5채널로 **0 패딩**한 것이다.
첫 conv 의 가중치를 `(16, 3, 3, 3)` → `(16, 5, 3, 3)` 으로 늘리고 **채널 3·4 를 전부 0**
으로 두었다. conv 는 입력 채널에 대한 합이므로 0 가중치 채널은 출력에 기여하지 않는다.

**검증 (실측):** 채널 3·4 자리에 **최대 ±459 크기의 무작위 잡음**을 넣은 `(2,5,64,100)`
입력과, 같은 앞 3채널만 넣은 `(2,3,64,100)` 입력의 출력을 5회 비교했다.

```
max|diff| = 0.000e+00   (5회 전부, 비트 단위로 동일)
```

즉 **슬롯 3·4 에는 무엇을 넣어도 된다** — 0, 잡음, 다른 노드의 데이터 무엇이든
점수가 바뀌지 않는다. 노드 4·5 를 나중에 실제로 쓰려면 **재학습이 필요하다.**

### ★ 슬롯 순서 — 노드 1·2·3 이 슬롯 0·1·2 에 그 순서로 들어가야 한다

```
입력 (1, 5, 64, 100)
   슬롯 0  <- 노드 1     ← 학습된 채널
   슬롯 1  <- 노드 2     ← 학습된 채널
   슬롯 2  <- 노드 3     ← 학습된 채널
   슬롯 3  <- (무시됨, 가중치 0)
   슬롯 4  <- (무시됨, 가중치 0)
```

**순서가 섞이면 shape 은 맞는데 점수가 조용히 틀린다.** 추론이 실패하지 않으므로
발견하기 어렵다. 노드 → 슬롯 매핑은 `node_id - 1` 이다
(`scripts/m1_runtime.py` 의 `align_to_grid` 와 동일).

노드 간 시각 정렬은 **`stream_id` 의 epoch** 로 해야 한다 (§1-2 참조).
`ts_ms` 로 정렬하면 노드가 서로 어긋난 채 들어가고, 이 역시 조용히 틀린다.

### 통합 레포에서 바꿀 것은 임계값 하나뿐이다

| 항목 | 변경 |
|---|---|
| `fall_detected` 임계값 | **0.7 → 0.80** |
| 그 외 (`_preprocess`, `_infer_onnx`, 로더) | **변경 없음** |

출력이 이미 0~1 확률이므로 `np.clip(score, 0.0, 1.0)` 도 그대로 두면 된다
(범위 안이라 아무 일도 하지 않는다). 임계값 0.80 의 근거는 §3 참조.

### ★ 파일명은 `m1_wifi_pose.onnx` 를 유지해야 한다

**통합 레포 로더가 이 이름을 찾는다.** 날짜나 노드 수를 붙여 바꾸면 로드되지 않는다.

## 4. 유의사항

### ★ 노드 수가 3이다 — 병합 전 반드시 확인

**9/14 팀 합의는 5노드였다.** 현장에 외장안테나가 없어 **내장안테나 보드 3대**로
수집했고, 모델도 3노드로 학습했다. ONNX 입력은 `[batch, 3, 64, 100]` 으로 고정돼 있다.

- 5노드를 넣으면 **shape 불일치로 추론이 실패한다** (조용히 틀리지는 않는다).
- 5노드로 가려면 **재수집 + 재학습**이 필요하다. 가중치 변환으로는 안 된다
  (첫 conv 의 입력채널 수가 다르다).
- 학습 코드는 `n_nodes` 를 설정으로 받으므로 1~8 어느 값으로도 재학습할 수 있다.

### ★★ 빈 방 발화율 — 이 수치가 배포 가능성을 결정한다

**사람이 없는 상태가 운영 중 가장 흔한 상태다.** 따라서 빈 방 발화율은 다른 어떤
지표보다 먼저 봐야 한다. 빈 방에서 자주 울리면 나머지 성능이 아무리 좋아도 배포할 수 없다.

| 임계값 | 빈 방 발화율 | 낙상 재현율 | 우도비 (재현율/빈방) |
|---:|---:|---:|---:|
| 0.30 | 92.4% (220/238) | 0.853 | **0.92** ← 발화가 낙상의 증거가 못 됨 |
| 0.50 | 51.7% (123/238) | 0.747 | 1.44 |
| 0.70 | 17.6% (42/238) | 0.564 | 3.20 |
| 0.75 | 6.7% (16/238) | 0.516 | 7.67 |
| **0.80 (권고)** | **1.3% (3/238)** | **0.480** | **38.08** |

측정 대상: 검증셋의 빈 방 세션 **2개(`1356`, `1358`) 합계 238창**.

**세션별로 나누면:**

| 세션 | 창 수 | @0.70 | @0.75 | **@0.80 (권고)** |
|---|---:|---:|---:|---:|
| `1356_normal_empty` | 119 | 22 (18.5%) | 10 (8.4%) | **2 (1.7%)** |
| `1358_normal_empty` | 119 | 20 (16.8%) | 6 (5.0%) | **1 (0.8%)** |
| **합계 (표에 실린 값)** | **238** | **42 (17.6%)** | **16 (6.7%)** | **3 (1.3%)** |

> 이전 판에서 "표는 @0.75 에 6.7% 인데 런타임 확인은 8.4%" 라는 불일치가 있었다.
> **둘 다 맞다. 모집단이 다르다** — 표의 6.7% 는 **두 세션 합계 16/238**,
> 런타임 확인은 `1356` **한 세션만 10/119 = 8.4%** 였다. 위 표에서 보듯
> `1356` 의 @0.75 는 정확히 8.4% 로 일치한다. **표 쪽(238창)이 기준값이다.**
> 세션이 2개뿐이라 세션 간 편차(1.7% vs 0.8% @0.80)가 그대로 드러난다.

**우도비가 1 미만인 구간(0.10~0.35)에서는 빈 방이 낙상보다 더 자주 울린다.**
그 임계값의 발화는 낙상의 증거가 되지 못한다. 이전 권고값 0.30 이 이 구간이었다.

### ★ 시드만 바꿔도 빈 방 거동이 10배 변한다 — 학습이 이 부분을 제약하지 못한다

같은 데이터·같은 설정에서 **시드만 달라졌을 때**:

| | PR-AUC | 빈 방 발화 @0.70 |
|---|---:|---:|
| 직전 학습 (ep8) | 0.472 | **1.7%** |
| 이번 산출물 (ep5) | 0.436 | **17.6%** |
| 변동 폭 | 0.41~0.47 | **1.7% → 17.6% (10배)** |

**PR-AUC 는 ±7% 안에서 움직였는데 빈 방 발화율은 10배 변했다.**
학습 목적함수가 빈 방 거동을 거의 제약하지 못하고 있다는 뜻이다.
**같은 설정으로 재학습해도 이 수치가 재현된다는 보장이 없다.**
이 문서의 모든 수치는 `models/m1_base_3node_20260916.onnx` **이 파일 한 개**에 대한 실측이다.

### 빈 방은 학습 데이터에서 이미 적지 않다 (`labels_split.csv` 기준)

| 구간 | 전체 창 | 빈 방 창 | 비율 | 빈 방 세션 |
|---|---:|---:|---:|---:|
| train | 2192 | **730** | **33.3%** | 8개 (1352·1353·1354·1355·1357·1359·1400·1401) |
| val | 924 | **238** | **25.8%** | 2개 (1356·1358) |
| 합계 | 3116 | 968 | 31.1% | 10개 |

train 창의 **1/3 이 이미 빈 방**이다. 그런데도 위와 같이 거동이 불안정하다.
**"빈 방 데이터가 적어서"로 단순히 설명되지 않는다** — 양을 더 늘리는 것만으로
해결될지는 확인되지 않았다. (참고: `imbalance.strategy = weighted_sampler` 라
음성 창은 역빈도로 가중치가 낮아져 실제 학습 노출은 33.3% 보다 적다.)

### 정규화 가설 — **미검증 (측정 수단이 없어 확인하지 못함)**

> 아래는 **가설이다.** 지지도 기각도 되지 않았다. 단정해서 인용하지 마라.

**관측된 사실 (실측):**
수집 CSV 의 `raw_*` 는 **이미 프레임 피크 정규화된 값**이다. 34 세션 표본
**17,034 프레임 전부에서 프레임 피크가 정확히 `1.000000`**
(최소 1.000000 / 최대 1.000000 / 표준편차 9.5e-08)이었다.
ESP 가 패킷 시점에 정규화한 뒤 기록하므로 **프레임 진폭 정보가 센서 단에서
이미 소실돼 있다.** 우리 학습·추론 파이프라인에는 배율이 도달하지 않는다.

**가설:**
낙상은 **진폭 급변**이, 호흡은 **진폭 변조**가 주요 단서다. 그렇다면 배율을 버리는
현재 전처리가 다음 두 가지를 **동시에** 설명할 가능성이 있다:

- **M1 의 빈 방 오탐** — 빈 방은 신호가 약해 정규화가 잡음을 전체 스케일로 끌어올린다
- **M2 의 느린 성분 부재** — lag-1 자기상관 0.05~0.11 로 시간적 연속성이 거의 없다

두 증상이 같은 원인(진폭 소실)에서 나올 수 있다는 것이 가설의 요지다.
**아직 검증되지 않았다.**

**검증하지 못한 이유:**

| 측정하려던 것 | 결과 |
|---|---|
| 정규화 직전 프레임 피크 `max\|H\|` 분포 (빈 방 vs 사람 있음) | **측정 불가** — 모든 프레임이 1.000000 |
| 창 단위 평균 피크 ↔ 모델 점수 상관계수 | **계산 불가** — 피크가 상수라 분산 0 |

**검증 방법 (펌웨어 협의 필요):**

1. 펌웨어에서 **정규화 전 프레임 피크값을 프레임당 float 하나**로 함께 전송한다
2. 수집 CSV 에 해당 컬럼(예: `raw_peak`)을 추가한다
3. **빈 방 세션과 사람 있는 세션(걷기·낙상)의 피크 분포를 비교**한다
   — 중앙값·사분위수, 그리고 창 단위 평균 피크와 모델 점수의 상관계수

비용은 **프레임당 float 1개**다. 대상 레포는 `safewave-ai-ambient-monitoring-firmware`.

> 참고: CSV 의 `resp_*` / `heart_*` 는 정규화돼 있지 않다
> (피크 중앙값 — 빈 방 0.0396 / 낙상 0.0530 / 걷기 0.0365). 다만 대역 필터를 거친
> M2 용 파생 신호라 "정규화 직전 raw 진폭"의 대체물이 아니다. **위 판정의 근거로
> 쓰지 않았다.**

### 10월 과제 우선순위

| 순위 | 과제 | 근거 | 비용 |
|---|---|---|---|
| **1** | **펌웨어에서 정규화 전 프레임 피크값 기록 → 위 가설 검증** | 현재 모든 프레임 피크가 1.000000 이라 M1 빈 방 오탐과 M2 느린 성분 부재를 동시에 설명할 수 있는 가설을 **확인할 수단 자체가 없다.** 이것부터 열어야 나머지 판단이 근거를 갖는다 | **프레임당 float 1개** |
| **2** | **시드 고정 후 빈 방 발화율을 모델 선택 기준에 포함** | 시드만 바꿔도 빈 방 발화가 @0.70 에서 1.7% → 17.6% 로 10배 변한다. 현재 조기 종료·best 선택이 `pr_auc` 만 보므로 빈 방 거동이 **선택 과정에서 전혀 제약되지 않는다** | 설정 변경 |
| **3** | **빈 방 손실 가중 조정** | 2순위로 선택 기준을 고친 뒤에도 남는 오탐에 직접 벌점을 준다 | 학습 코드 수정 |
| — | 빈 방 데이터 추가 | **최우선에서 내렸다.** train 창의 **33.3%(730/2192)가 이미 빈 방**이라는 실측이 근거다. 양이 부족해서라는 설명이 성립하지 않는다. **다만 배제하지는 않는다 — 양을 늘리면 나아지는지는 측정된 바 없다(미검증).** | 수집 |

> 1순위를 먼저 두는 이유: 2·3순위는 "빈 방에서 안 울리게 누르는" 처방이고,
> 1순위는 "왜 울리는지"를 확인하는 작업이다. 원인이 진폭 소실이라면 2·3순위로는
> 증상만 눌리고 M2 쪽 문제는 그대로 남는다. **비용이 프레임당 float 하나라
> 먼저 해볼 값이 충분하다.**

### 하드 네거티브를 학습에 넣으면 오히려 나빠진다

| 학습 구성 | val 창 | 양성 비율 | PR-AUC | 베이스라인 대비 |
|---|---:|---:|---:|---:|
| **하드 네거티브 제외 (이번 산출물)** | 924 | 0.2435 | **0.436** | **1.79배** |
| 하드 네거티브 포함 | 1200 | 0.1875 | 0.283 | **1.51배** |

**양성을 늘리지 않은 채 음성만 추가하면 안 된다.** 하드 네거티브 45건을 넣으면
양성 비율이 0.2435 → 0.1875 로 떨어지고, 모델은 음성 쪽으로 쏠린다.
다음 수집에서는 **낙상 양성을 함께 늘려야** 한다.

## 5. 이 수치들의 한계

1. **1인 · 1실 · 1일 데이터다.** 피험자·환경 일반화는 검증되지 않았다.
2. **검증셋 양성이 낙상 19건에서만 나온다.** 양성 225창 중 129창(57%)이
   한 세션(`csi_20260916_1327_fall.csv`)에서 온다. 지표 분산이 크다.
3. **노드 커버리지 평균 약 89%** 다. epoch 격자 정렬에서 약 11% 슬롯이 0 으로 패딩된다.
   이 손실이 성능에 주는 영향은 측정하지 않았다.
4. **rp5 실기기에서는 재지 않았다.** 모든 수치는 학습 PC 추론이다.
5. **8/2 걷기 32% 는 단일노드 구모델을 rp5 실시간으로 잰 값**이라 이번 창 단위
   측정과 같은 자가 아니다. 방향만 읽어야 한다.
6. 하드 네거티브 7 세션은 학습에서 제외했으므로 §4 의 발화율은 **미학습 데이터
   기준**이다 — 그만큼 깨끗한 측정이지만, "아직 안 가르친 것을 못 맞힌다"는
   당연한 결과이기도 하다.
