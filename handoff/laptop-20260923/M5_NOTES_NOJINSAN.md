## 7. 09-24 정확도 개선 실험 — 모델 고정(1.5B), 노트북 긴 프롬프트
### 7-1. 평가 기준부터 고침
- **정답 파일이 낡아 있었음**: `qwen_eval_dataset.json`이 "낙상 확정 → 0.65" 규칙 이전 것 → 9건 정답이 달랐다. 이제 평가 때마다 현재 규칙으로 다시 계산한다.
- **주 지표 = 운영 구간**(게이트 ≥ 0.6, 실제로 M5가 불리는 케이스). normal 58건은 운영에서 M5까지 오지 않는다.
- **정답 v2(판정표)**: 게이트 등급을 기본으로, 아래는 critical — ① 위기 생체신호 + (낙상 확정·위험음·긴급키워드) ② 낙상 확정 + (위험음·긴급키워드) ③ 게이트 critical. (심박·호흡 동시 위기만 있는 경우는 warning — 판단 필요 시 바꿀 것)
- **held-out 무작위 150건**(`--random 150 --seed N`): 프롬프트 예시를 평가셋 100건에 맞춘 효과가 새 케이스에도 가는지 확인. seed 924는 조정에 썼고, **최종 수치는 조정에 안 쓴 seed 2024**.

### 7-2. 바꾼 것 (`SLM_PROMPT_PROFILE=laptop`, RPi5 기본 `rpi5`는 프롬프트 그대로)
| 항목 | 내용 |
|---|---|
| 지시문 | 입력 읽는 법 + critical/warning/normal 판정표 명시 |
| 입력 | 상태 문장 뒤에 `게이트규칙:낙상확정,생체위기…`(등급은 critical일 때만 — 등급을 적으면 1.5B가 그대로 복사) |
| 예시 | 6개 → 21개(normal 4·warning 6·critical 11), 평가셋과 값이 겹치지 않게. 예시 정답이 판정표와 같은지 단위 테스트로 확인 |

| 길이 | 약 740 → 약 2,730토큰. `n_ctx` 4096, `QWEN_GGUF_CACHE_MB` 256(1.5B KV ≈ 28 KB/토큰) |

| 시도 후 뺀 것 | llama.cpp 출력 문법(GBNF): 정확도 차이 0~1건, 지연 GPU +0.8 s·CPU +1.1 s |

## 8. 09-24 저녁 — 정확도 95% 이상 (모델 1.5B Q5 고정)
### 8-1. 채택한 것 (노트북 프로필에만 적용, RPi5 짧은 프롬프트는 그대로)
| 방법 | 내용 |
|---|---|
| **유사 예시(retrieval few-shot)** | 고정 예시 21개 뒤에 입력과 가장 비슷한 판정표 라벨 예시 3개를 붙인다. 예시 풀 = 심박·호흡·낙상·환경음·키워드 격자 288개, 라벨·근거는 `rubric_level`. 가장 비슷한 예시를 입력 바로 앞에 둔다 |
| 예시 근거에 "왜 critical이 아닌지" | warning 예시에 `위험음·키워드·위기 없음` / `낙상 확정 아님·위기 없음` 등을 붙임 — 없으면 소견이 여럿일 때 critical로 올림 |
| 등급 우선 | 모델 등급과 점수 구간이 어긋나면(warning인데 0.4) 점수를 등급 구간으로 맞춤 — 점수가 권위값이라 normal로 떨어지던 문제 |
