작성: 노진산(통합). 모델 `whisper_onnx_int8_ft_svc`(기본값), 운영 코드(`WhisperSmallModel`) 그대로, 코드 develop `5d85860`.

- 9/17 fp32(직접 녹음 28개 CER 44.2%, 키워드 46.4%) 대비 INT8 파인튜닝이 크게 좋아졌습니다.
- 직접 녹음(실제 사용 조건에 가까움)은 여전히 AI Hub보다 3~4배 틀립니다.
- 평가 세트가 개발에 쓰인 세트라 최종 독립 결과로는 보고하지 않습니다.

## 3. 환각 (공유가 필요한 부분)
노트북 USB 마이크로 방 소리를 받을 때(VAD -45 dB), 조용하고 짧은 조각에서 없는 문장이 나왔습니다.
- **"MBC 뉴스 이덕영입니다" / "이준석입니다" / "이범귀입니다"** 등: 0.3~0.5초, 최대 음량 -38 dB 이하 조각
- "감사합니다", "경제였습니다", "날씨가 좋았다"
- 반복형: "기사에 비해 국가대표의 정책에 비해 국가대표의 정책에 비해 …"
- **위험한 것**: 잡음 조각에서 "도와줘", "너 죽어", "넘어져보이잖" → 긴급 키워드 오경보로 이어질 수 있음

통합 쪽 임시 조치: 노트북 VAD를 -35 dB·최소 500 ms로 올려 조각 수를 줄였습니다(RPi5는 -45 유지).
보류 중인 제안(의견 부탁드립니다):
1. 알려진 환각 문장 제거(“MBC 뉴스 … 입니다”, “시청해 주셔서 감사합니다”, “구독과 좋아요” 등)
2. 너무 짧거나(예: 0.5초 미만) 작은 조각은 전사 결과를 버리기
3. 반복 방지 guard(인계 때 주신 wrapper) 통합 — 아직 미통합

참고: M3 병합으로 sensing이 **조용한 이벤트를 peak 0.85까지 증폭**한 뒤 보냅니다(M4 입력도 증폭됨). 환각에 영향이 있는지 봐 주시면 좋겠습니다.

## 4. 속도
| 환경 | M4 1회 | RTF |
|---|---|---|
| RPi5 INT8(9/17) | 4.43 s | — |
| 노트북 CPU 2스레드(RPi5 설정) | 1.00 s | 0.38 |
| 노트북 CPU 8스레드 | 0.65 s | 0.19 |
| 노트북 GPU | 0.47 s | 0.14 |

- GPU에서는 INT8 연산 상당수가 CPU로 돌아가 CPU↔GPU 복사 노드가 168~268개 생깁니다. GPU용이라면 **FP16 모델**이 더 빠를 것 같습니다(필요하면 비교해 보겠습니다).
- 통합 쪽에서 GPU 모드일 때 transformers pipeline이 모델을 CPU로 되돌리던 문제를 고쳤습니다(`b23ad5f`, `device=model.device`).
